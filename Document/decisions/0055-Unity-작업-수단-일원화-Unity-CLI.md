# ADR-0055 — Unity 작업 수단 일원화: Unity CLI

- 상태: 채택 (2026-10-26)
- 관련: ADR-0001(하네스 엔지니어링 도입), [[harness]]

## 배경

Sandbox·Builds 2Proc 세 Unity 프로젝트에 에디터 연동용 git 패키지가 설치되어 있었고, pi 하네스도 에디터 연동 서버에 접속하는 구성이었다. 이 방식은 에디터 프로세스가 살아 있어야 하고 연결 상태에 따라 검증 경로가 흔들리며, 종료코드·로그·NUnit XML 같은 재현 가능한 배치 증거와 별개의 수단을 요구한다. 반면 저장소는 이미 Unity CLI 배치 관례(`-runTests` 전수 실행, `run2proc.sh` 2-프로세스, `UniNetSolutionGenerator` sln 재생성)로 검증해 왔다.

## 결정

1. **에디터 연동 도구 완전 제거** — 세 프로젝트의 패키지 매니페스트·잠금 파일에서 해당 항목을 제거하고 패키지 캐시를 삭제한다. pi 하네스의 에디터 연동 서버 등록도 제거한다.
2. **Unity CLI 일원화** — Unity 관련 작업(테스트 실행·솔루션 재생성·씬·빌드 자동화)은 배치 모드 CLI로만 수행한다. 명령 관례는 [[harness]] "Unity 작업 수단" 절을 따른다.
3. **증거 계약** — 종료코드, `-logFile`, NUnit XML을 남긴다(로그·XML은 `Builds/` 아래 보존).
4. **문서 표기 원칙** — 하네스·프로젝트 문서에서 제거된 도구를 언급하지 않는다("에디터 연동"으로 지칭). 과거 검증 이력의 기록 문장은 역사 기록으로 보존한다.

## 기각한 대안

- 연동 도구 유지 + CLI 병행: 검증 경로 2종 유지비와 불일치 위험. 증거 재현성이 낮은 쪽에 의존하게 된다.

## 결과

- 설치 본체(매니페스트·잠금·캐시·서버 등록) 제거. batchmode 재해석 실행으로 패키지 없이 정상 임포트됨을 확인한다(검증 게이트).
- 규칙 신설: [[harness]] "Unity 작업 수단" 절 + `AGENTS.md` 프로젝트 사실. 하네스 변경은 [[changelog]]에 기록했다 (doc-sync).
