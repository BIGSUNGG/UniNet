# 0035. 씬 전환 동기화

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 10 (씬 전환 동기화)

## 배경 (Context)

ADR-0025로 씬 로드 후 재등록은 되지만, "서버가 모든 클라에 씬 전환을 지시하고 전원 준비를 기다리는" 조율이 없어 게임이 매번 직접 구현해야 했다.

## 결정 (Decision)

1. **서버 API** `NetworkServer.LoadScene(sceneName)` — 전 연결에 씬 식별자 브로드캐스트(와이어 11) + 준비 추적 시작. 클라 보고(와이어 12) 시 `IsClientSceneReady(connId)` 표시, 전원 준비 시 `AllClientsSceneLoaded` 이벤트 발화(메인 스레드).
2. **클라 자동 흐름** — 생성 허브가 와이어 11 수신 → `UniNetManager.OnSceneTransitionRequested(sceneName)` 메인 큐 → `SceneManager.LoadScene` → ADR-0025 재등록 → `ReportSceneLoaded(sceneName)` 와이어 12 전송 (드라이버 sceneLoaded 콜백에서 자동). 제너레이터 0.2.7.
3. **연결 해제 시 게이트 재판정** — 퇴장 연결을 준비 집합에서 제거 후 게이트 재확인(마지막 연결 퇴장으로 게이트 완성 가능).

## 결과 (Consequences)

- **긍정**: 로비→전투 흐름의 프레임워크 조율 — 게임은 LoadScene 호출 + AllClientsSceneLoaded 구독만.
- **부담 / 리스크**: 서버도 자체 씬 로드는 게임 책임(LoadScene은 브로드캐스트+게이트만). 씬 이름 문자열 비교 — 빌드 씬 이름 불일치 시 게이트 미발화(타임아웃은 게임 책임). 후발 접속자도 캐치업 시 진행 중 전환에 참여(Welcome 직후 SendLoadScene 재발송, 게이트가 후발자 보고까지 대기).
- **폐기 방법**: LoadScene 호출 안 하면 기존 동작.
