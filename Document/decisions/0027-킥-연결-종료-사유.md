# 0027. 킥·연결 종료 사유 전달

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 2 (킥·연결 종료 사유)

## 배경 (Context)

상용 운영 최소 요건이 결여돼 있었다 (실사용 갭 검토 2026-10-12 치명 ②):

1. 서버가 악성·미인증 클라를 강제 퇴장시킬 공개 API가 없었다 (`DetachConnection`은 내부용).
2. `ClientDisconnected`가 인자 없는 `Action`이라 클라가 **서버 종료 / 네트워크 유실 / 의도적 퇴장을 구분 불가** — 재접속 시도 여부 판단의 기본기. "접속 후 토큰 인증→거부" 패턴 자체가 불가능했다.

제약: DRPC/Communication 상류는 수정하지 않는다 (ADR-0021 패키지 고정). 전송계층 `DisconnectReason`(Error/FlowControl/Local/Remote/Timeout)은 연결해제 데이터 페이로드가 없어 킥 사유를 실을 수 없다.

## 결정 (Decision)

1. **애플리케이션 계층 사유 enum** `UniNetDisconnectReason` (None/ClientStopped/ServerShutdown/Kicked/ConnectionLost) — 와이어 시스템 메시지 6번(신규)으로 전달. 제너레이터 0.2.2.
2. **서버 킥 API** `NetworkServer.DisconnectClient(connId, reason = Kicked)` — 공지를 **와이어에 플러시한 뒤**(SendAndFlush — SendAsync는 큐 등록만이므로), 150ms 유예 후 전송 연결 폐쇄. 유예는 클라의 fire-and-forget 비동기 디스패치(DRPC ProcessRequestAsync)가 공지를 닫힘 데이터그램보다 먼저 처리하도록 보장한다. 폐쇄 후 `DetachConnection`→소유권 재배정·수명주기 이벤트는 기존 경로 그대로.
3. **서버 정지 공지** — `ServerStopAsync`는 `BroadcastDisconnectNoticeAsync(ServerShutdown)`을 플러시 대기 후 리스너 폐기. 동기 `ServerStop`(종료 경로)은 파이어앤포겟(최선 노력).
4. **클라 이벤트 서명 변경(파괴적)** — `UniNetManager.ClientDisconnected: Action<UniNetDisconnectReason>`. 공지 수신 시 사유 저장(`NetworkClient.LastDisconnectReason`), 전송 `Disconnected` 발화 시 저장 사유 없으면 `ConnectionLost`로 승격. 자발적 `ClientStop` 미발화 계약 유지.
5. 최선 노력 계약: 공지가 죽어가는 연결과 함께 유실되면 클라는 `ConnectionLost`로 강등 — UX(재접속 프롬프트 vs 메뉴 복귀) 구분은 유지된다.

## 결과 (Consequences)

- **긍정**: 인증 실패·치트 대응 퇴장·버전 거부(항목 3 연계)의 기반. 클라 UX 분기 가능. Arena HUD에 퇴장 사유 표시 예시.
- **부담 / 리스크**: `ClientDisconnected` 서명 변경 — 구독자는 `Action<UniNetDisconnectReason>`로 마이그레이션. 킥/서버정지 폐쇄가 공지 플러시+150ms 지연(의도적 폐쇄에만 적용, 일반 해제 무관). 150ms 유예는 경험적 상수 — 극단적 부하에서 공지가 경합에 밀리면 ConnectionLost로 강등(계약상 허용).
- **폐기 방법**: 상류가 연결해제 페이로드를 지원하면 시스템 메시지 6번을 대체해 데이터그램에 실는다.
