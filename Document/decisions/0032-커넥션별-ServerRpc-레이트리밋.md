# 0032. 커넥션별 ServerRpc 레이트리밋

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 7 (RPC 레이트리밋)

## 배경 (Context)

ADR-0016 소유권 강제는 위조(타 오브젝트 netId)를 막지만, **정당 소유자의 플러드**는 서버가 그대로 실행한다 — 매크로·치트가 이동/발사 RPC를 초당 수백 회 쏘면 서버 틱·대역폭·게임 로직이 소모된다. 실사용 갭 검토 2026-10-12 높음 ⑦: "RPC 스팸 방어는 상용 치트 대응 기본기".

## 결정 (Decision)

1. **고정 1초 창 게이트** — `NetworkServer.ServerRpcRateLimitPerSecond`(커넥션별 호출/초, 0=무제한 기본·옵트인). 생성 디스패치 람다가 핸들러 실행 **전** `AllowsServerRpc(senderConnId)`로 검사(제너레이터 0.2.5). 초과 호출은 드롭(빈 응답 반환 — one-way 호출은 응답 폐기라 무해)되고, 경고 로그는 ADR-0016 정적 스로틀(첫 1회/송신자 + 5초당 1회)을 재사용해 플러드가 로그를 채우지 못한다.
2. **상태 분리** — 레이트 창은 연결 레지스트리와 별도 `ConcurrentDictionary`(창별 락)로 디스패치 스레드가 연결 락과 경합하지 않는다. 시계는 Stopwatch(스레드 안전 — Unity 시계는 메인 스레드 전용, ADR-0029 교훈). 연결 분리 시 창 제거.
3. **통계 노출** — `RateLimitedServerRpcDrops`(전체·Interlocked)·`GetRateLimitedServerRpcDrops(connId)`. ADR-0029 통계 라인과 함께 운영 관측.

## 결과 (Consequences)

- **긍정**: 플러드/매크로 방어 기본기. 기본 무제한이라 기존 게임 무영향. Arena가 관대한 상한(120/s — 정상 플레이 피크 약 20/s) 설정 예시.
- **부담 / 리스크**: 고정 창 경계 버스트(창 경계 2배) 허용 — 토큰 버킷이 정밀하나 창·상태가 더 단순해 고정 창 채택(게임 상한은 여유 있게 설정). 게임별 RPC별 한도(이동 vs 발사)는 필요 시 확장. 서버 시간 창이라 클라 시계 왜곡 무관.
- **폐기 방법**: 한도 0으로 두면 게이트 무효(기본값).
