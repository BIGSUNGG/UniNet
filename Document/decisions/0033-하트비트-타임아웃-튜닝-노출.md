# 0033. 하트비트 타임아웃 튜닝 노출 (상류 릴리스 경로)

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 8 (하트비트 타임아웃 튜닝 노출 — 사용자 선택 A: 상류 릴리스 경로)

## 배경 (Context)

유지(하프오픈) 타임아웃 — 무패킷 상태가 지속되면 피어를 끊어진 것으로 판정하는 RUDP `DisconnectTimeout`(기본 5000ms) — 을 게임이 환경에 맞게 튜닝(모바일·불안 네트워크는 10~15초, 민첩 검출은 단축)해야 하는데, **상류 DRPC 공개 API에 전달 경로가 없었다**: `RpcEndpointOptions` → `HubSessionFactory.CreateTransportOptions` → `RpcHost/Client` 공개 오버로드 어디에도 `DisconnectTimeout` 파라미터가 없다(전송 옵션에는 필드가 있으나 DRPC가 조립 후 도달 불가). 대안: (a) 상류 DS_RPC에 전달 추가 후 패키지 릴리스 (b) 리플렉션 (c) 필드만 깔고 전달 미룸(계약 미충족). 사용자 결정: **(a) 상류 릴리스 경로**.

## 결정 (Decision)

1. **DS_RPC 3.6.1 (로컬)** — `RpcEndpointOptions.DisconnectTimeoutMs`(양수=적용·0=전송 기본 5000ms·음수 거부) + `CreateTransportOptions(disconnectTimeoutMs)` 선택 파라미터(기존 호출처 전부 호환) + `ToTransportOptions` 전달. DS_RPC 저장소 문서(changelog·README·skills/drpc) 동기. 로컬 피드(`C:/Projects/DS/unity-nuget`) 패킹 — nuget.org 미게시(게시는 DS_RPC 소유 세션에서).
2. **기반 스택 동반 갱신** — DRPC 3.6.0이 요구하는 형제 스택(Communication 2.7.1·MessageProtocol 3.2.1·LiteNetLib 2.1.4·BouncyCastle 2.7.0) nupkg를 nuget.org에서 로컬 피드로 확보, `update-dlls.sh` 버전 핀 갱신(DRPC 3.5.0→3.6.1·Communication 2.7.0→2.7.1·MessageProtocol 3.2.0→3.2.1), DLL 재추출.
3. **UniNet 노출** — `UniNetEndpointOptions.DisconnectTimeoutMs`(같은 계약) → `ToRpcEndpointOptions` 전달. 기본 0(전송 기본 유지) — 소비자 무변경.

## 결과 (Consequences)

- **긍정**: 모바일 등 환경별 튜닝 가능. UniNet의 1Hz RTT 프로브(ADR-0029)가 트래픽을 유지하므로 이 창은 "진짜 침묵"만 잰다(프로브가 꺼져도 전송 자체 하트비트 역할). 기반 스택이 3.6.x 라인으로 승격되어 향후 상류 개선 수용 여건 확보.
- **부담 / 리스크**: DRPC 3.6.1이 로컬 전용(미게시) — DS_RPC 게시 시점까지 로컬 피드 의존(ADR-0021 로컬 피드는 문서화된 운영 방식). 버전 라인 혼재 주의(nuget.org 3.6.0에는 이 기능 없음).
- **폐기 방법**: DisconnectTimeoutMs 0으로 두면 전달 비활성(기본값).
