# ADR-0050 — 서버 입력 만료 정책은 옵트인 (hold-last 기본 유지)

- 상태: 채택 (2026-10-21)
- 관련: ADR-0034(유예 세션), ADR-0038(예측·결정론), ADR-0042(소유권 스트림), ADR-0049(사망 게이트), MOV-003(감사 항목)
- 버전: 0.14.0

## 배경

`MoveSimulation.TickServer`는 입력 큐가 비면 마지막 입력(`_input`)을 무기한 재적용한다(hold-last 외삽 — 기존 문서 계약). 이때 문제 상황: 클라가 살아있지만 입력 전송이 끊긴 상태(렉·일시정지·네트워크 단절) 또는 ADR-0034 유예 세션(유예 소유자는 `ReassignOwnership`에서 건너뛰므로 오브젝트는 소유자 있음으로 서버가 계속 시뮬)에서 **마지막 전진 입력이 유예/단절 내내 재적용**된다 — 의도치 않은 무한 주동(벽 뚫기 포함).

업계 관행은 갈린다: UE도 서버 move 부재 시 hold-last 유사(연결 타임아웃 킥 계층으로 처리), FishNet은 입력 부재=정지. UniNet은 hold-last를 기본으로 채택해 왔다.

## 결정

1. **`MoveSimulation` 생성자에 옵트인 옵션 `inputExpirySteps`(기본 0=비활성)를 추가한다.** 0이면 오늘과 완전히 동일(hold-last 무기한) — 기존 게임 코드는 재컴파일만으로 무영향(기존 5개 호출부는 6-인자 형태 유지, 소스 호환). ADR-0034 `SessionGraceSeconds`(기본 0=옵트인)와 동일 패턴.
2. **만료 도달 틱에 `_input = default(TInput)`을 정확히 1회 스왑하고, 이후 새 입력이 채택될 때까지 default를 계속 적용한다(멱등).** decay-to-zero 같은 점진 감쇠는 기각 — `TInput` 필드의 의미(스칼라 스케일 가능 여부)는 게임만 알고, Step의 순수성·결정론 계약(ADR-0038)을 프레임워크가 임의 변형할 수 없다. `default` 폴백만이 안전한 프레임워크권 동작이며, "정지"가 아닌 default를 가진 게임은 문서의 계약 문구로 자기 입력 의미를 인지해야 한다.
3. **경계 3곳(`OnTeleport`·`ResetOwnershipStream`·`DropPendingHistory`)에서 만료 타이머를 0화한다.** 사망 게이트 종료 후에는 신선한 만료 창을 준다(게이트 진입 전 카운트를 이월하지 않음). 소유권 임기 경계(ADR-0042)와의 결합은 없다 — 타이머는 시퀀스 상태와 무관한 독립 카운터.
4. **인터페이스(`INetworkMoveSimulation`)는 변경하지 않는다.** 옵션은 구체 타입 생성자에만 존재 — 사용자 구현체는 자체 만료 정책을 자유롭게 갖는다. `NetworkTransform` 편의 노출(프롭)은 범위 밖(YAGNI — 확장 포인트로 남김).

## 기각한 대안

- **무수정+문서화**: 유예 세션과 결합하면 프레임워크가 유예 중 무기한 주동하는 모양새이고, 만료가 필요한 게임이 TickServer 대체물을 직접 구현해야 한다(인터페이스가 게임 구현체를 강제 — 비용 과대).
- **기본 on(기존 hold-last 폐기)**: hold-last를 전제로 한 기존 게임이 깨진다 — 계약 파괴.
- **decay-to-zero 감쇠**: 위 2항 근거.

## 결정 2 — SetInput도 만료 창을 연다 (r19 ISSUE-1, 같은 릴리스)

만료 카운터를 큐 기아만 세면 리슨서버 호스트의 로컬 입력이 만료된다 — 호스트 입력은 `AdoptInput`을 거치지 않고 매 프레임 `SetInput`으로 갱신되기 때문(`ArenaPlayer.HandleLocalInput` 경로). 계약 문언("inputless TickServer steps")과 동작을 일치시키기 위해 **`SetInput`도 `_idleSteps`를 0으로 리셋**한다: 살아있는 입력 공급(호스트 SetInput 연속 갱신)은 만료되지 않는다. 전용 서버는 SetInput을 호출하지 않으므로 무영향. 핀 테스트: T6(SetInput 60틱 연속 갱신 무만료)·T7(음수 생성자 거부 — r19 ISSUE-2).

## 결과

- 사용자 계약: 기본은 hold-last 무기한(문서화된 기존 계약 유지). `inputExpirySteps > 0`이면 입력 공급이 그 스텝 수만큼 끊기면 default 입력으로 봉인되고, 새 입력 채택 시 hold가 재개된다(창 재오픈).
- 와이어·생성기·인터페이스 무변경. 런타임 공개 API 변화는 `MoveSimulation` 생성자 선택적 파라미터 추가뿐(minor 버전 0.14.0).
