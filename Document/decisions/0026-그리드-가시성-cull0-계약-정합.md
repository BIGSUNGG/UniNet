# 0026. 그리드 가시성에서 cull=0 항상 관련 계약 복원

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 1 (클라→서버→다른 클라 이동 동기화 단절 해결)

## 배경 (Context)

P3 가시성 계약: `NetworkCullDistance = 0`은 "거리 컬 미적용 — 항상 관련". 그러나 P4 그리드 가시성(`SetVisibilityGrid`, ADR-0012) 구현이 cull=0 오브젝트에도 그리드 멤버십 판정을 적용해, 뷰어 위치 기준 그리드 반경 밖이면 컬했다. cull=0의 의미가 그리드 모드에서만 뒤집히는 계약 불일치.

소비 사고: 아레나(MPPM)에서 그리드+연결별 뷰어 위치 조합으로, 컬 거리를 설정하지 않은 플레이어 아바타가 서로의 그리드 반경 밖으로 나가면 화면에서 사라지는 **클라→서버→다른 클라 이동 동기화 단절** 발생 (서버 화면에서는 정상 이동 확인 — 서버 시점 컬 문제로 좁힘).

대안:

1. **cull=0 그리드 판정 제외 (본 결정)** — P3 계약을 전 모드에서 일관되게 유지.
2. Arena에서 그리드 사용만 중단하고 라이브러리 계약 유지 — 계약 불일치가 남아 모든 소비자에게 같은 함정 재발.
3. 별도 "항상 관련" 옵트인 API 추가 — cull=0으로 이미 같은 의미를 표현 중이라 불필요 (YAGNI).

## 결정 (Decision)

그리드 멤버십 판정은 `NetworkCullDistance > 0` 오브젝트에만 적용한다. cull=0 오브젝트는 어떤 모드에서도 컬되지 않는다 (P3 계약 전 모드 일관). 그리드는 cull>0 오브젝트의 **공간 예비 필터**(양자화 오차 ≤ cellSize)로 기능하며, 통과 후 자체 컬 거리 판정과 AND된다. 관련성 훅(`IsNetworkRelevant`)·뷰어 미설정 fail-open·P3 전이 계약(첫 평가 조용한 시드, 재진입 기준선 복구)은 종전 유지.

아레나 예제는 그리드·뷰어 위치 사용을 제거한다(소규모 아레나는 거리 컬 불필요 — 컬 거리를 설정하는 오브젝트가 없어 뷰어 위치는 데드 웨이트였음).

## 결과 (Consequences)

- **긍정**: 모드 간 계약 일관("cull=0 = 항상 관련" 무조건 성립), 소비자 함정 제거, 회귀 테스트 추가(`GridVisibilityTests.그리드_활성_시_cull_미설정_오브젝트는_반경_밖이어도_항상_관련이다`).
- **부담 / 리스크**: 대규모 월드에서 그리드 공간 컬의 효과는 컬 거리를 설정한 오브젝트에만 발생 — 그리드 도입 가이드에 "오브젝트에 `NetworkCullDistance` 설정 필요" 명시(README·skills 갱신 완료).
- **폐기 방법**: "항상 관련" 성격의 별도 옵트인 API(UE bAlwaysRelevant 대응)를 도입할 때 재검토.
