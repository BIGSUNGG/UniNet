# 0047. 게임 접속 승인 콜백 — 와이어 7 자격 증명과 ConnectionApprover

- **상태**: 승인됨
- **날짜**: 2026-10-21
- **결정자**: 사용자(일괄 사전승인 범위) · 플래너 설계(zai/glm-5.3-flash) · 워커 구현

## 배경 (Context)

감사 대장 CON-002: `UniNetEndpointOptions`에는 공통 연결 키만 있고 게임별 자격 증명을 검사하는 접속 승인 확장점이 없다. CON-001(ADR-0043)이 버전 선언 수용 전 게임 데이터 유보를 구현했지만, 서버가 검사하는 것은 버전 문자열뿐 — 게임이 자체 인증(DB/토큰 검증)으로 접속을 승인/거부할 방법이 없었다. UE Network Framework의 `PreLogin/PreLoginAsync`(UE_5.7 GameModeBase)가 동일 역할: 클라가 보낸 옵션의 토큰을 검사하고 거부 사유를 전달하며, 승인 전엔 액터 복제가 없다.

## 결정 (Decision)

1. **자격 증명 전달 = 와이어 7 페이로드 확장** `[version string][credential string]` — 클라는 항상 2문자열을 기록(`ConnectionCredential` 옵션, 기본 빈 문자열), 서버는 상한 검사(4096바이트, 파싱 전 조용 폐기 — ADR-0041 선례) 후 버전을 읽고 **잔여 바이트가 있을 때만** credential을 읽는다(조건부 읽기). 구 서버는 뒤 문자열을 안 읽고(느긋한 읽기), 신 서버+구 클라는 잔여 0으로 credential="" 처리 — 양방향 호환.
2. **승인 콜백 = `UniNetEndpointOptions.ConnectionApprover` 위임 필드** `Task<bool> UniNetConnectionApprover(UniNetApprovalRequest{ConnId, ProtocolVersion, Credential})` — null(기본)이면 CON-001 동작 그대로. 비동기 우선(DB/HTTP 검증), 동기 게임은 `Task.FromResult`. 콜백은 메인 스레드에서 시작하며 재개는 thread pool → `QueueOnMain(FinishApproval)`으로 메인 복귀(상태 변경은 메인 계약 유지).
3. **거부 = 기존 킥 경로 + `UniNetDisconnectReason.ApprovalRejected = 6`** — 공지 플러시→150ms 유예→폐쇄 재사용, 클라는 `ClientDisconnected(ApprovalRejected)`로 관측. 자유 텍스트 사유는 과잉으로 제외(클라 UX 매핑은 게임 몫). 열거값 명시 지정·재번호 없음 — 비파괴.
4. **비동기 대기 중 = CON-001 유예 상태 재사용** — `VersionApproved` false 유지로 유보(재배정·캐치업·복제·스폰·LoadScene·ClientConnected·게임 ServerRpc 게이트 `UnapprovedServerRpcDrops`)가 자동 적용. `ApprovalRequested` 플래그로 콜백 연결당 1회 보장(재선언 멱등 — 이미 승인된 연결은 재검증 안 함).
5. **타임아웃 = `VersionDeclareTimeoutMs`를 "선언+승인 콜백 완료까지의 총 예산"으로 재사용** — 스윕이 콜백 진행 중 연결도 미승인으로 VersionMismatch 킥(무기한 유보 없음; UE PreLoginAsync 미완료 hang 경고와 같은 이유). 느린 인증 게임은 옵션 상향.
6. **재접속(ResumeSession) 경로도 wire 7을 항상 보내므로 동일하게 콜백 1회 통과** — 게임이 재검증하거나 통과시킨다(문서화).

## 결과 (Consequences)

- **긍정**: 게임이 데이터 노출 전에 자격 증명을 검사해 접속을 승인/거부한다 — 계정 서비스 구축 없이도 인증 게임 서버의 최소 요건 충족. 거부는 기존 킥 경로 재사용으로 사유가 클라에 전달된다.
- **부담 / 리스크**: (a) 콜백의 게임 코드는 메인 스레드에서 시작 — await 이후 유니티 API 접근은 게임이 QueueOnMain 등으로 처리(표준 Unity 비동기 규칙 문서화). (b) 게임 콜백의 반환 Task는 **메인 스레드 펌프와 무관하게 완료 가능해야 한다**(DB/HTTP I/O형 — 내부 await에 `ConfigureAwait(false)`) — 메인 스레드 캡처 continuation은 메인이 막혀 있으면(테스트·백그라운드 에디터) 완료가 굶는다(EditMode 검증에서 실측). (c) 콜백 hang은 총예산 스윕이 VersionMismatch 킥으로 마감 — 느린 인증 게임은 `VersionDeclareTimeoutMs` 상향 필요. (d) 자격 증명은 평문 전송 — 와이어 암호화(DTLS 옵션)와의 조합은 게임 배포 책임.
- **폐기 방법**: `ConnectionApprover` null이 기본 동작이므로 옵션·델리게이트·구조체·`ApprovalRejected` 값을 제거하고 wire 7 핸들러를 1문자열 읽기로 되돌리면 된다. `ApprovalRejected` 값은 재번호 금지 — 폐기 시에도 값 보존.

## 마이그레이션

없음 — 옵션·델리게이트·열거값 추가만 존재(기존 API·와이어 7 구 클라 호환 유지). 생성기 0.2.13(와이어 7 페이로드 확장 송수신), 패키지 0.10.0. 콜백 미설정 서버는 CON-001 동작과 완전히 동일하다.
