# 0009. P2 완결 — 동적 스폰/파괴·조건부 리플리케이션·InitialOnly

- **상태**: 승인됨
- **날짜**: 2026-09-16
- **결정자**: DS + pi

## 배경 (Context)

- P2 잔여 항목(로드맵 기준: 스폰/파괴 동기화·조건부(COND_OwnerOnly)·InitialOnly)을 구현해 P2를 완결한다 (ADR-0008 구현의 후속).
- **사용자 결정 1 — 스폰 사용법**: 일반 `Instantiate`/`Destroy` 자동 감지(씬 폴링 스캔)를 검토했으나, 서버 인스턴스에서 원본 프리팹 식별이 런타임에 불가능해 클라 생성 지정 수단이 반드시 필요하고 틱마다 전체 씬 스캔 비용이 상용 서버에 부담되므로 **명시적 API 방식**(Mirror/Netcode/UE SpawnActor 관례)으로 확정.
- **사용자 결정 2 — 네트워크 역할**: `NetworkRole` enum(Authority/AutonomousProxy/SimulatedProxy)은 기존 불린 3종(IsServer/IsClient/IsOwner)과 중복되는 API 표면이라 **미추가** (Unity 생태계 관례도 불린 — Mirror·Netcode for GameObjects). 로드맵 '네트워크 역할 개념' 행은 불린으로 충족 처리.

## 결정 (Decision)

1. **동적 스폰/파괴 — 명시적 API** (`UniNet.Unity.UniNetManager`):
   - 서버에서 `Instantiate(prefab)` 후 **`UniNetManager.Spawn(instance)`** — netId 할당·소유권 배정(라운드로빈 즉시)·전 클라 스폰 전파. **`UniNetManager.NetworkDestroy(instance)`** — 전 클라 파괴 전파 + 로컬 파괴. 서버 권위 — 비서버 호출은 경고 후 무동작.
   - **netId 공간 분리**: 동적 오브젝트는 서버가 증분 카운터로 할당(등록 테이블 충돌 검사 포함). 씬 오브젝트의 경로 해시와 독립.
   - **클라 생성 우선순위**: `RegisterPrefab<T>(prefab)` 타입 카탈로그 → 소스젠 기본 팩토리(빈 GameObject + AddComponent). 프리팹 식별이 불가하므로 카탈로그는 **타입 키 기반**(한 타입 = 프리팹 1개). 타입 키 = 전체 이름 FNV-1a 64.
   - **스폰 메시지**: `[netId][typeKey][pos 3][quat 4][전체 상태 페이로드]` — 변환(위치·회전)은 스폰 시 1회 전파. 이후 이동은 [Replicated] 필드(예: 좌표 float)로 동기화하는 게임 코드 책임.
   - **후발 접속 캐치업**: 연결 확정 시 Welcome → 소유권 재배정 → 기존 오브젝트 일괄 전달(동적=스폰 메시지, 씬=전체 상태 리플리케이션). 수신 그룹별 조건(OwnerOnly/SkipOwner)은 캐치업에도 적용.
   - **호스트 이중 생성 방지**: 호스트의 클라는 자기 서버가 스폰한 오브젝트를 새로 만들지 않고 **서버 인스턴스를 클라 등록으로 재사용**.
2. **조건부 리플리케이션 + InitialOnly — 생성자 flags enum**:
   - `[Replicated(ReplicateCondition.OwnerOnly, Notify = nameof(X))]` — `ReplicateCondition`: None/OwnerOnly/SkipOwner/InitialOnly 비트 조합. OwnerOnly|SkipOwner 동시 지정은 컴파일 타임 진단 **UNINET010**으로 거부.
   - **수신 그룹별 페이로드**: 서버 틱은 필드 조건별로 소유자용/비소유자용 2종 델타를 계산해 전송. 조건 필드가 없는 타입은 동일 페이로드 재사용(핫패스 계산 1회 유지).
   - **InitialOnly**: 델타 비교·전송에서 제외. 스폰/캐치업 전체 상태에만 포함(이후 서버 값 변경은 전파 안 됨).
   - **스냅샷은 수신 그룹별로 분리하지 않는다**(공유 1본): 어느 그룹에 보냈든 틱마다 1회 갱신. 소유자가 없는(0) 상태에서 변경된 OwnerOnly 필드는 이후 새 소유자에게 중간값이 유실될 수 있다 — 최소 구현의 명시적 계약. 그룹별 마지막 전송 상태 추적은 P3(가시성·우선순위)에서 재검토.
3. **호스트 권위 원본 보존**: 클라의 리플리케이션 적용(`__UniNetApplyIn`)에서 **서버 등록 인스턴스(IsServer)는 값 재기록을 스킵**한다(Notify는 유지). 근거: 호스트는 서버·클라가 같은 인스턴스를 공유하므로 이미 권위 값인 필드에 역직렬화 값을 다시 쓰면 — 특히 [Message] 참조 필드에서 사본 인스턴스로 교체되어 스냅샷 참조 비교 dirty가 **매 틱 재발**하는 무한 churn이 생긴다(구현 중 발견, PlayMode로 재현·검증).
4. **고스트 등록 방어**: 드라이버(`UniNetDriver`)가 매 프레임 등록 오브젝트를 Unity-null 검사해 일반 `Destroy`로 사라진 오브젝트도 파괴 전파(리소스 소진 방어). `ponytail:` O(n) 순회 — 오브젝트 수가 커지면 파괴 이벤트 후크로 교체.
5. **클라 API 정리**: `NetworkClient.RegisterSceneObject` → `Register(netId, instance)`로 통일(씬·동적 공용) + `Unregister`. 서버 `RegisterSceneObject`는 유지, `RegisterDynamicObject` 추가.

## 결과 (Consequences)

- **긍정**: P2 완결 — 동적 오브젝트 생애주기(스폰·상태·파괴·후발 합류)와 UE COND_ 계열 핵심 조건(OwnerOnly/SkipOwner/InitialOnly) 지원. 사용법은 `Spawn`/`NetworkDestroy` 호출 2개 + 속성 인자. 핫패스(조건 없는 타입) 계산량 불변.
- **부담 / 리스크**: 타입-프리팹 카탈로그 1:1 제약(한 NetworkBehaviour 타입에 프리팝 여러 개 불가 — 필요 시 명시적 API 확장). 스폰 변환은 최초 1회(이후 이동은 필드 리플리케이션 필요). parenting(계층 구조 동기화) 미지원. OwnerOnly 필드의 소유자 부재 시 변경 유실(위 2의 계약). 소유권은 여전히 라운드로빈 최소 정책(명시적 이전 API는 계속 후순위).
- **폐기 방법**: 스폰 사용법·조건 계약 변경 시 새 ADR로 대체.

## 알려진 한계·후속 과제

- ADR-0008 한계 승계: 접속 직후 첫 전송 레이스·ServerRpc 발신자 미검증·연결 종료 수명주기(Stop/Shutdown).
- **같은 프로세스 재시작 미지원** — 호스트/서버를 한 프로세스에서 여러 번 시작하는 시나리오(테스트 등)는 이전 스택이 정리되지 않는다(Stop 미구현의 연장).
- 캐치업 전송은 연결 1개당 전체 오브젝트 순회 — 대규모 월드에서는 스트리밍/관심 영역 도입 필요(P3 가시성과 연동).
