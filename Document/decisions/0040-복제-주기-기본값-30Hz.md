# 0040. 복제 주기 기본값 30Hz

- **상태**: 승인됨
- **날짜**: 2026-10-13
- **결정자**: 사용자 + pi

## 배경 (Context)

ADR-0039(복제 배칭과 신뢰성 분리)로 아레나 데모의 메시지 수 과다를 해소하면서 전송 주기(`NetworkUpdateFrequencyHz`)는 게임이 오브젝트마다 직접 설정하는 옵트인 정책(기본 0 = 틱마다 무제한)이었다. 이 때문에 **정책을 설정하지 않는 다른 프로젝트는 여전히 모든 오브젝트가 틱 레이트 그대로 복제**되어 같은 메시지 수 과다 문제가 재발한다. 요청: "다른 프로젝트에서도 이와 같은 문제가 발생하지 않게 복제 주기 기본 값을 설정해."

대안: (a) 라이브러리 기본값 30Hz — Arena가 검증한 값, 수 시뮬 스텝이 델타 1개로 병합, (b) NetworkTransform만 기본 설정 — 이동 외 일반 상태는 여전히 무제한, (c) 문서만 권장 — 재발 방지 효과 없음.

## 결정 (Decision)

`NetworkBehaviour.NetworkUpdateFrequencyHz`의 기본값을 **0(무제한)에서 30으로** 바꾼다. 주기 미도달 틱은 비교를 생략하고 도달 틱에 최신 변경분을 보내는 기존 P3-④ 계약(최신값 승)은 그대로다. 무제한이 필요한 오브젝트는 `NetworkUpdateFrequencyHz = 0`으로 옵트인한다. 즉시 모드(`TickReplication(objects)` — P2 호환 경로)는 주기 정책을 적용받지 않는다.

## 결과 (Consequences)

- **긍정**: 정책을 설정하지 않는 프로젝트도 기본적으로 틱 레이트가 아닌 30Hz 스트리밍 cadence를 얻는다 — 60Hz 틱에서 스텝 2개가 델타 1개로 병합되어 메시지 수가 절반 이하로 감소. Arena의 명시적 30Hz 설정은 이제 기본값과 일치(데모 문서화 목적으로 유지).
- **부담 / 리스크**: 매 틱 전송에 의존하던 기존 소비자 코드는 동작이 달라진다(최대 33ms 지연) — 와이어 포맷은 불변이지만 행위 기본값의 파괴적 변경이므로 이 버전(0.3.0)의 체인지로그에 명시한다. 30Hz로도 부족한 고빈도 오브젝트는 0(또는 더 높은 값)으로 명시한다.
- **폐기 방법**: 기본값을 0으로 되돌리면 ADR-0011(P3)의 원래 계약으로 복귀한다.
