# 0014. 스폰 서브 자동 복원 — 멀티 컴포넌트 오브젝트의 RegisterPrefab 필수 요건 완화

- **상태**: 승인됨
- **날짜**: 2026-09-20
- **결정자**: DS + pi

## 배경 (Context)

- NetworkTransform 컴포넌트(ADR-0013) 도입 후, `[RequireComponent]`로 결합된 멀티 컴포넌트 오브젝트(ArenaPlayer + NetworkTransform)의 클라 스폰에서 **"스폰 슬롯 불일치 — 서버 서브 2개/클라 1개"** 런타임 에러가 발생했다.
- 원인: 클라 스폰 경로(`UniNetSpawn.Apply`)가 **첫 서브 타입의 기본 팩토리/카탈로그로만** 오브젝트를 생성 — 기본 팩토리는 단일 컴포넌트만 추가하므로, 서버의 나머지 서브와 슬롯 수·구성이 어긋났다.
- 기존 계약(ADR-0010): 멀티 컴포넌트 오브젝트는 `RegisterPrefab`으로 양단 같은 프리팹을 등록하는 것이 **필수**. 그러나 스폰 메시지에는 서브 구성 전체(typeKeys[])가 이미 포함되어 있어 클라가 스스로 복원할 수 있다.

## 결정 (Decision)

1. **클라 서브 자동 복원**: `UniNetSpawn.Apply`가 첫 서브 생성 후, 스폰 메시지의 typeKeys 순서대로 누락된 NetworkBehaviour 서브를 `UniNetSpawnRegistry.TypeOf(typeKey)`로 타입을 조회해 `AddComponent`로 복원한다.
   - 순서 보장: 추가는 typeKeys 순서대로 수행되며 `VerifySlots`로 최종 대조한다 — 서버 슬롯 순서와 동일 구성만 수용.
   - 미등록 타입 키: 스폰 전체를 거부하고 부분 생성물을 폐기한다(부분 생성 방지).
   - 첫 서브 경로는 유지: 카탈로그 프리팹(RegisterPrefab) 우선 → 기본 팩토리. **프리팹의 나머지 서브 누락분도 자동 복원된다.**
2. **계약 완화**: 멀티 컴포넌트 오브젝트의 `RegisterPrefab`은 **필수 → 선택**으로 완화된다. 프리팹 등록은 커스텀 비주얼·사전 구성이 필요한 경우에만 사용한다.
3. **호스트 경로 불변**: 호스트는 서버 컴포넌트 배열을 재사용하므로(ADR-0009) 본 변경의 영향이 없다.
4. **범위 밖**: 2-프로세스 실측(사본 프로젝트 필요 — 환경 비용), 서브별 프리팹 조합 캐시.

## 진단 기록 — 이동 동기화 단절의 근원 (2026-09-20 사용자 리포트)

- **증상**: MPPM에서 클라가 이동하면 본인 화면에선 움직이지만 다른 클라 화면에선 제자리(서버 화면에선 움직임 확인).
- **진단**: 본 결함(스폰 슬롯 불일치)으로 **다른 클라에서 멀티 컴포넌트 오브젝트(플레이어+NetworkTransform)의 스폰이 거부**되어, 서버가 권위 위치를 갱신해도 다른 클라에는 오브젝트·NetworkTransform 서브가 없어 위치 델타가 무용화 — "이동 동기화 단절"의 제1 원인.
- **제2 원인 (자동 복원 이후에도 재발 가능)** — NetworkTransform의 [Replicated] 위치 3필드에 **Notify(OnNetX/Y/ZChanged) 미연결**: 필드 갱신은 되지만 Notify가 불리지 않아 리모트 인터폴레이션 버퍼가 영구 비었고, 다른 클라 화면에 이동이 반영되지 않음. → 3필드 Notify 연결로 해소. 아울러 NetworkTransform.SubmitMove가 클라에서 로컬 예측 입력(_inX)을 갱신하지 않는 결함도 함께 수정(예측 즉시 반영 복원).
- **결론**: 본 ADR의 자동 복원 + 제2 원인 수정으로 해소된다. 회귀 방지 테스트(`UniNetSpawnApplyTests.Apply_2서브_스폰을_순서대로_복원하고_위치_상태도_적용한다`)가 "복원 + NetworkTransform 위치 상태 수신 → 인터폴레이션 버퍼 적재(렌더 준비)"까지 단언한다.

## 결과 (Consequences)

- **긍정**: `NetworkTransform` 추가만으로 멀티 컴포넌트 오브젝트가 양단에서 동일 구성으로 스폰된다 — RegisterPrefab 누락 런타임 에러 클래스 소멸. "사용은 간단하게" 원칙 복원.
- **부담 / 리스크**: 미등록 NetworkBehaviour 타입이 RequireComponent 체인으로 끼어들면 스폰이 거부된다(명확한 에러 메시지로 진단 가능). 서브 복원은 마지막 서브 이후 1회 수행 — 서버가 슬롯을 제거하는 방식의 변경에는 대응 불가(기존 계약).

## 검증 증거 (2026-09-20)

- **EditMode 52/52** — 신규 `UniNetSpawnApplyTests` 4종: 2서브 복원+SubId/netId 주입, 역방향 순서 보존, 미등록 타입 키 거부(부분 생성 폐기), 단일 서브 기존 동작 회귀. `MultiComponentTests`의 구 계약 단언(불일치 거부)을 자동 복원 계약으로 갱신 — 복원분(HealthTank)에 전체 상태(Armor 77) 적용까지 검증
- **PlayMode 12/12** — 아레나 전체 회귀 그린

## 알려진 한계·후속 과제

- 프리팹 경로에서 프리팹이 스폰 메시지보다 많은 서브를 갖는 경우 — 초과분은 거부된다(서버 구성이 기준).
- 2-프로세스 실측은 미실행(사본 프로젝트 환경 비용) — 러너 갱신은 후속.
