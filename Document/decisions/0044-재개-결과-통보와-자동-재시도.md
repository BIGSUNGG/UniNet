# 0044. 재개 결과 통보와 자동 재시도 — REC-001

- **상태**: 승인됨
- **날짜**: 2026-10-20
- **결정자**: 사용자 승인 방향(부모 확정 설계) · worker 구현

## 배경 (Context)

ADR-0034의 `ReconnectAsync` 반환 true는 **연결 수립**일 뿐 재부착 결과가 아니었다(감사 REC-001). 서버 `ResumeSession`의 bool은 생성 허브 핸들러에서 폐기되고, 클라에게 결과를 알리는 와이어가 없어 — 성공은 소유권 통보로만 간접 추론 가능했고 거절은 완전 침묵이었다. 특히 빠른 재접속 경합(서버가 구연결 죽음을 감지하기 전 재접속 — 유예 세션이 아직 저장 안 됨)은 무조건 침묵 실패해 그 연결은 영구 신규 플레이어가 됐다. 이중 소비 경합의 패자도 조용히 실패했다.

## 결정 (Decision)

1. **`GraceResumeResult` 열거형 반환** — `NetworkServer.ResumeSession`이 `Reattached / SessionNotFound / Expired / UnknownToken`을 반환한다(기존 bool 파괴 교체). 미생성 경합=SessionNotFound, 만료=Expired, 소진/불일치/무효 연결=UnknownToken. SEC-001 계약 유지: 어떤 실패도 세션을 소진하지 않는다.
2. **wire 14 재개 결과 통보** — 모든 종결 사유가 요청 연결로 전송된다: `ResumeResult{ok, reason, retryableRemainingMs}`. SessionNotFound에는 재시도 가능 창(유예 시간)이 실린다 — 서버는 "아직 저장 안 된 경합"과 "없는 토큰"을 구분할 수 없어 전자일 가능성이 있는 한 재시도 창을 연다. `IUniNetSystemChannel.SendResumeResult`는 기본 no-op(테스트 채널 무변경), 생성 서버 허브가 wire 14 송신을 구현한다. 생성 클라 허브가 `RegisterClient(14)` 수신기를 등록하고 `NetworkClient.ApplyResumeResult`가 `LastResumeResult`·`ResumeResultReceived` 이벤트(디스패치 스레드 — `QueueOnMain` 마셜)로 노출한다. 제너레이터 0.2.10.
3. **소비/만료 토큰 툼스톤** — 세션 소진·스윕 만료 시 토큰을 `(reason, expiry)`로 짧게 기억해 이중 소비 패자는 **UnknownToken**, 스윕된 만료는 **Expired**로 정확히 종결된다(SessionNotFound 재시도 오인 방지). 툼스톤은 원 만료 시점에 스윕에서 정리된다(유예 창 하나분으로 상한).
4. **자동 재시도** — 클라가 SessionNotFound + 재시도 창을 받으면 드라이버 Update 캐던스로 wire 10을 0.5초 간격 재전송한다(`NetworkClient.TickResumeRetry` — 종결 결과 또는 창 마감까지). 디태치 경합이 재부착으로 수렴한다. 재시도 데드라인은 메인 스레드 첫 틱에 계산한다(Unity 시계의 비메인 스레드 예외 — CON-001 교훈).
5. **`ReconnectAsync` 계약 문서화** — 반환값은 여전히 "재접속 시도 수립"이며 재부착 성공 아님; 결과는 `ResumeResultReceived`로 관측한다.

## 결과 (Consequences)

- **긍정**: 재개 성공/거절이 명시적·양방향(와이어 14) — 게임이 "같은 플레이어 재입장 vs 신규 입장"을 이벤트로 구분. 디태치 경합 자가 수렴. 이중 소비 패자 즉시 종결. 클라 재시도로 유예 창 내 재부착 성공률 상승.
- **부담 / 리스크**:
  - **파괴 변경**: `ResumeSession` bool → `GraceResumeResult`(직접 호출자 마이그레이션 — 기존 false는 종결 사유로, true는 `Reattached`로). 와이어 14 신규 — 구형 클라(0.6.x 생성 허브)는 미등록 methodId 수신(하위호환은 부모 실기 확인; DRPC 미등록 methodId는 무시될 것으로 보나 실증 필요).
  - SessionNotFound의 재시도 창은 없는 토큰(추측)에도 열린다 — 각 재시도는 SessionNotFound로 거절되고 세션을 소진하지 않으므로(SEC-001) 무해하나 공격자가 창 동안 0.5초 간격 재전송을 유도할 수 있다(레이트리밋·버전 승인 게이트가 이미 앞선다).
  - 토큰 없는 신규 접속은 wire 14를 받지 않는다(이벤트 미발화 — 신규 입장은 ClientConnected로 구분).
- **폐기 방법**: wire 14 송수신·`TickResumeRetry` 호출·툼스톤을 제거하고 `ResumeSession`을 bool로 되돌린다(제너레이터 0.2.9).
