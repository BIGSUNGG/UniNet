# 0008. P1 RPC + Replicate 기본 구현 아키텍처

- **상태**: 승인됨
- **날짜**: 2026-09-14
- **결정자**: DS + pi

## 배경 (Context)

- ADR-0007로 확정한 사용법 API를 실제 동작시키는 첫 구현 (범위: P1 전체 + P2 기본 — 동적 스폰/파괴·조건부·InitialOnly 제외).
- 목표 계약은 "사용법 파일 바이트 보존"이었으나, 구현 착수 전 **Roslyn 소스 제너레이터는 새 코드 추가만 가능하고 기존 메서드 본문 진입을 가로챌 수 없다**는 구조적 한계가 확인됐다 (Mirror·NGO·FishNet이 IL 위빙을 쓰는 이유). 사용자 결정으로 **옵션 2 — 순수 소스젱 + 사용법 재구조화**(partial 선언형)로 전환했다. IL 위빙·런타임 디투어(IL2CPP 비호환)는 배제.
- DRPC·MP 각 제너레이터와 UniNet 제너레이터의 체이닝은 불가능하다 (같은 컴파일 패스에서 제너레이터는 서로의 출력을 볼 수 없음).

## 결정 (Decision)

1. **사용법 패턴 재구조화 (사용자 승인)** — RPC 메서드는 `partial` 선언 + 본문은 `{Name}_Implementation` + 선택 `{Name}_Validate`(`Task<bool>`, DRPC Validation 패리티). MulticastRpc 클라 호출 시 로컬 전용 계약은 유지.
2. **UniNet.CodeGenerator** (`CodeGenerator/`, netstandard2.0·MC.CSharp 4.3.0=Unity 6.0 LTS Roslyn, nupkg → `unity-nuget/` 피드 → NuGetForUnity RoslynAnalyzer 라벨 설치) — NetworkBehaviour 파생을 스캔해 단일 `UniNet.Generated.g.cs` 방출:
   - 서버/클라 허브: `ServerHub<,>`/`ClientHub<,>` 상속 + **DRPC 런타임 수동 구성 API**로 직접 배선 (`MethodCallActions`/`MethodDeliveryModes` 등록, `HubSessionFactory.CreateRudpSession`, `RpcHost.ListenAsync`/`RpcClient.ConnectAsync`). DRPC.CodeGenerator를 거치지 않는다 — 체이닝 문제 원천 회피.
   - 타입별 partial 구현(송신 분기·서버 디스패치·검증 후크)·리플리케이션 델타 핸들·`UNINET0xx` 진단(partial 미선언·미지원 타입·구현 누락·시그니처 불일치·ID 충돌).
   - 직렬화는 **MessageProtocol 런타입 프리미티브(`MessageBufferWriter/Reader`)를 직접 방출** — MP 제너레이터와의 체이닝 회피. 지원 타입: 기본형 12종 + string.
3. **다중 어셈블리 지원** — 전역 디스패치 테이블(`UniNetDispatch`)에 각 어셈블리가 수신 핸들 등록, 어떤 어셈블리의 허브가 리슨하든 전체 메서드 디스패치. 송신은 `UniNetEnvironment.ClientSender`/`IUniNetSystemChannel.UniNetSend` 슬롯으로 어셈블리 무관.
4. **런타임 (`Package/Runtime/`)**:
   - `UniNet.Core.Hosting` — NetworkServer(연결·소유권·리플리케이션 틱), NetworkClient(Welcome·소유권 맵), UniNetEnvironment(메인 스레드 펌프 — 네트워크 스레드 디스패치를 Unity Update에서 실행), UniNetEndpointOptions(DRPC `RpcEndpointOptions` 래핑 — ConnectionKey·CRC32c·DTLS 1.2 인증서/핀닝 동등 노출, **게임 코드는 DRPC·MP 타입을 직접 몰라도 된다**).
   - `UniNet.Unity` — NetworkBehaviour(netId·IsOwner·IsServer/IsClient), UniNetManager(Host/Server/ClientAsync), UniNetDriver(숨은 구동기).
   - **netId = 씬 경로 해시**(FNV-1a 64, 형제 인덱스 포함) — 양단 무합의 일치. 동적 스폰은 범위 밖.
   - **소유권 라운드로빈 최소 정책** — 연결 순서×netId 정렬 순환 배정. `ponytail:` 실서비스 요구 시 명시적 이전 API로 대체.
   - **dirty 검출은 폴링 비교** — 필드 셋터 후킹 불가(위빙 배제)의 대가. 틱마다 스냅샷 대조, 변경분만 전송.
5. **상류 처리 규칙 결과** — DRPC 3.5.0 런타임 공개 API(허브 베이스·팩토리·옵션 전부 public)로 요구가 충족되어 **DS_RPC·DS_MessageProtocol 수정은 불필요**했다 (Orca 오케스트레이션 경로 미발동).

## 결과 (Consequences)

- **긍정**: 순수 Roslyn 파이프라인(Unity 6 에디터 내장)만으로 전 기능 동작 — IL 위빙 없음, IL2CPP 친화적(reflection 미사용). 상류 무수정. 다중 어셈블리·테스트 어셈블리 지원.
- **부담 / 리스크**: 사용법이 선언형으로 바뀌어 ADR-0007 원안과 달라짐(본 ADR로 대체 기록). 폴링 dirty·라운드로빈 소유권은 성장 한계(주석 표기). RPC 매개변수·리플리케이션 필드가 기본형+string으로 제한(진단 UNINET002).
- **폐기 방법**: 사용법 패턴·아키텍처 변경 시 새 ADR로 대체.

## 알려진 한계·후속 과제

- **접속 직후 첫 전송 레이스** — 클라 접속 완료 직후(Welcome/소유권 수신 전) 보낸 one-way RPC 1건이 유실 관측됨. 세션 활성화와의 레이스로 추정 — DRPC/Communication 상류(DS_RPC·DS_Communication) 조사 후보. 자연 사용 패턴(연결 확정 후 RPC)은 무영향.
- **ServerRpc 발신자 미검증** — 완화 플러밍 완료(연결별 허브가 발신 connId를 디스패치까지 주입, `senderConnId`). 소유권 대조 강화는 후속. features 문서 '알려진 한계' 참조.
- **연결 종료 수명주기(Stop/Shutdown) 미구현** — 후속 과제.
