# 0038. 상태 기반 이동 예측 일반화 — 게임 정의 입력·상태 구조체

- **상태**: 승인됨
- **날짜**: 2026-10-13
- **결정자**: /goal "점프, 구르기, 대시, 텔레포트와 같은 기능을 사용할 수 있게 이동 동기화 기능의 확장성을 늘려" (계약 확정: 최대 유연 일반화 + 파괴적 API 전환 허용 + Arena 점프·대시·텔레포트 실증 + 고정 스텝 재시뮬)

## 배경 (Context)

ADR-0013 NetworkTransform·ADR-0037 FullReconciliation의 이동 규칙은 `(위치, 3축 float 입력, dt)`의 **무상태 순수 함수**(`MovementStep`)만 지원했다. 점프(중력·수직 속도)·대시/구르기(쿨다운·시간 창)는 규칙 자체에 상태가 필요해:

- 히스토리에 상태가 없어 롤백 시 과거 속도로 되감지 못함 — 재시뮬이 발산, 반복 롤백
- 입력 채널이 3축 float 고정이라 버튼 엣지(누른 순간)를 인코딩 불가
- 재시뮬 dt가 `Time.deltaTime` 단일 값 근사(ADR-0037 명시 부담 사항) — 결정론 깨짐

사용자 요구: 이런 상태 기반 이동을 프레임워크 차원에서 정확한 CSP&R로 지원.

## 결정 (Decision)

1. **게임 정의 입력·상태 구조체 + 순수 스텝 규칙** — `MoveSimulation<TInput, TState>`(UniNet.Core, 순수 C#)이 표준 구현. 게임은 5개 정적 함수 주입: `Step(ref state, ref x,y,z, in input, dt)` + 입력/상태 Write/Read 코덱(ADR-0020 커스텀 직렬화 계약과 같은 형태). 구조체는 값 필드면 제한 없음(Unity 타입 포함) — 어셈블리 경계를 직렬화 바이트만 넘는다.
2. **고정 스텝 시뮬레이션** — 양단이 같은 `StepIntervalSeconds`로 스텝(기본 60Hz). dt는 항상 고정값 → 재시뮬 결정론 보장(ADR-0037 dt 근사 부담 해소). 소유 클라는 직전 두 스텝 사이 렌더 보간.
3. **입력 스트림 + 시퀀싱** — 소유 클라가 매 스텝 `(seq, 입력 blob)`을 `RpcSubmitMove` ServerRpc로 전송(소유자 강제 ADR-0016·레이트리밋 ADR-0032 자동 적용). 서버는 큐(용량 8, 포화 시 최旧 폐기)에서 스텝마다 1개 채택, 비면 최신 입력 외삽(UE 방식). 스테일/재생 seq·오버사이즈·불량 페이로드는 기각.
4. **상태 에코 롤백** — 서버가 채택 시 `(ackSeq, 위치, 상태 blob)`을 OwnerOnly 복제(필드 선언 순서 = 적용 순서: 위치 → 상태 → ackSeq(Notify)). 클라는 ack 시 해당 seq 예측 위치와 비교, `RollbackThresholdSq` 초과 시 서버 상태 복원 후 미승인 입력 재생 — **속도·쿨다운이 포함된 상태까지 정확 복원**. ack가 히스토리 창(128엔트리 ≈ 2.1s) 밖이면 하드 스냅.
5. **와이어 운반** — 입력 blob은 `[Message] UniNetBlobEnvelope`(byte[] Data)로 RPC 파라미터 전달(제너레이터 무변경). 상태 blob은 같은 envelope 타입의 `[Replicated(OwnerOnly)]` 필드 — 인스턴스 교체가 참조 비교 델타 검출기를 작동시켜 전체 치환 전송. **envelope은 UniNet.Unity에 둔다** — MessageProtocol 소스젠이 애널라이저 패키지 폴더(UniNet.Unity/Analyzers) 기준 하위·참조 어셈블리에만 적용되어 UniNet.Core는 생성 커버리지가 없음(발견 경위: PlayMode 실패).
6. **텔레포트/리스폰** — `SetNetworkPosition`(서버)이 시뮬 상태 초기화(점프 궤적이 목적지에서 재개되지 않게). 입력 대기 없는 소유 클라 재앵커는 ADR-0037 경로 계승(대기 중 입력이 있으면 롤백 경로로 수렴).
7. **파괴적 API 전환** — `MovementStep`/`MovementRule`/`SubmitMove`/`PredictOwner`/`SoftRate`/`FullReconciliation` 제거. `Simulation`(주입)·`SimulationEnabled`·`InterpolationDelay`·`RollbackThresholdSq`·`SnapThreshold`(텔레포트 감지) 유지. 소비자(Arena·테스트) 동반 마이그레이션.

## 결과 (Consequences)

- **긍정**: 점프·대시·구르기·텔레포트급 이동이 옵트인 플래그 없이 기본 계약으로 정확한 CSP&R 지원. 게임은 구조체+5개 정적 함수만 작성. UE `CharacterMovement.MoveAutonomous` 수준의 결정론(고정 dt·상태 복원).
- **부담 / 리스크**:
  - 입력 스트림이 상시 전송(기본 60Hz × ~수십 바이트) — 대기 중에도 중력 등 시뮬레이션 진행을 위해 필요(UE와 동일). "정지 상태 압축"은 후속 최화 포인트.
  - 상태 blob이 스텝마다 신규 배열 할당(작음: 전형 수십 바이트) — GC 민감 대규모 서버면 풀링 확장 여지.
  - 서버·클라 스텝 레이트가 프레임 레이트보다 낮으면(스탈) 외삽 오차 증가 — 롤백이 수렴시키지만 빈도 상승. MaxStepsPerFrame=8로 스파이럴 가드.
  - 다른 클라가 보는 위치는 델타 리플리케이션+인터폴레이션 — 유효 지연은 도착 간격 EMA 기반 적응(상한 InterpolationDelay=0.12s), 텔레포트 불연속은 스냅으로 렌더(같은 세션 후속 수정).
- **폐기 방법**: `NetworkTransform.Simulation = null` — 위치 복제 전용으로 동작(ADR-0013 계약).
