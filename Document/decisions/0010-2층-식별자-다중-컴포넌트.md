# 0010. 2층 식별자 — GameObject 단위 netId + NetworkBehaviour SubId

- **상태**: 승인됨
- **날짜**: 2026-09-16
- **결정자**: DS + pi

## 배경 (Context)

- ADR-0009 시점까지 한 오브젝트에 NetworkBehaviour가 여러 개면: 동적 스폰은 첫 컴포넌트만 등록(경고), 씬 오브젝트는 netId(경로 해시)가 충돌해 마지막 등록만 생존(무경고) — 다중 컴포넌트 미지원이 명시적 제약이었다.
- 요구: UE Actor/Component처럼 한 게임오브젝트에서 여러 네트워크 컴포넌트가 각자 RPC·리플리케이션을 돌게 한다.
- **기각한 대안 — 컴포넌트별 독립 netId**: 구현은 싸지만 P3(가시성·우선순위·dormancy·전송 주기)의 단위가 UE에서 액터 단위인 것과 어긋나고(멀어서 안 보이는 적의 일부 스트림만 끊기는 등), 오브젝트당 스트림 N배, "이 오브젝트의 네트워크 상태" 질의가 불가능해진다. **선례**: UE(Actor 채널 내 서브오브젝트 리플리케이션)·Mirror(모든 RPC에 `[netId][componentId]`) 모두 "정체성은 오브젝트 1개, 컴포넌트는 내부 주소".

## 결정 (Decision)

1. **2층 식별자** — 네트워크 엔티티는 **GameObject 단위 netId 1개**(할당 규칙은 ADR-0008/0009 유지: 씬=경로 해시 무합의, 동적=서버 증번). 각 NetworkBehaviour는 오브젝트 내 슬롯 **`SubId`(byte, GetComponents 순서)** 를 받아 독립적으로 RPC·리플리케이션된다. 소유권·파괴·(향후 P3 가시성·우선순위)은 오브젝트 단위.
2. **와이어 포맷** — RPC `[netId][subId][인자...]`, 리플리케이션 `[netId][subId][mask][값...]`(서브별 델타·조건 마스크), 스폰 `[netId][변환 7값][subCount][{typeKey, stateLen, state}×N]`(서브슬롯은 순서 암시, state는 명시 길이 프레이밍), 파괴 `[netId]`(오브젝트 전체). 포맷 변경(기존 구현 간 호환 깨짐)은 0.x로 수용.
3. **등록·스폰** — 씬 등록은 오브젝트당 1회 + 컴포넌트 배열(경로 해시 충돌 소멸). 동적 `Spawn`은 **전 컴포넌트를 서브 테이블로 등록**(기존 "첫 것만" 제약·경고 삭제). 클라는 스폰 메시지의 서브 구성과 생성 오브젝트의 컴포넌트를 **슬롯·타입별로 대조**해 불일치 시 진단 후 거부.
4. **다중 컴포넌트 동적 스폰은 `RegisterPrefab` 필수** — 기본 팩토리(빈 GameObject+AddComponent)는 단일 컴포넌트만 만들 수 있어 슬롯 대조에서 거부된다. 카탈로그 키는 첫 NetworkBehaviour 타입.
5. **구성 불변식** — 런타임 AddComponent/DestroyComponent로 NetworkBehaviour를 증감하면 안 된다(양단 슬롯 불변식). 같은 타입 컴포넌트 중복은 허용(슬롯이 구분). **오브젝트당 NetworkBehaviour 상한 255개**(SubId가 byte) — 스폰/씬 등록에서 거부·로그, 서버 등록 최종 방어(예외).
6. **Core 재구성** — `ServerObjectEntry`가 서브 테이블(`SubObjectEntry[]`: instance·핸들러·typeKey·스냅샷)을 가진다. `NetworkClient` 등록도 `object[]`. 서버·클라 조회 `Get(netId, subId)`. 캐치업은 동적=스폰(전 서브 상태), 씬=서브별 전체 상태.

## 결과 (Consequences)

- **긍정**: 한 오브젝트에서 역할별 네트워크 컴포넌트(이동/체력/장비…) 분리 — UE Component 리플리케이션 상당. P3 기능(가시성·우선순위·dormancy·전송 주기)이 오브젝트 단위로 자연 부착. 씬 다중 컴포넌트 netId 충돌 소멸.
- **부담 / 리스크**: 와이어 +1바이트/subId·스폰 구성 나열. 서브별 리플리케이션 메시지 분리(오브젝트당 단일 패킷 병합은 P3 최적화 여지 — UE 액터 채널화). 슬롯 안정성이 양단 프리팹/씬 동일성에 의존(불일치 시 스폰 거부 진단으로 방어). 같은 오브젝트 컴포넌트 간 순서가 등록 순서라는 점을 문서로 계속 안내.
- **폐기 방법**: 식별 모델 변경(예: 컴포넌트 독립 netId) 시 새 ADR로 대체.

## 알려진 한계·후속 과제

- 슬롯 불변식 위반(런타임 컴포넌트 증감)은 스폰 시 대조로만 감지 — 씬 오브젝트의 증감은 감지 창구가 없다(문서 계약).
- 서브별 메시지 분리 — 오브젝트당 단일 패킷 병합·대역폭 통합은 P3.
- ADR-0008/0009 한계 승계(접속 직후 레이스·발신자 미검증·Stop/Shutdown).
- 2-프로세스 검증 중 발견한 테스트 함정 2건 기록: 카탈로그 템플릿이 씬 등록에 섞이는 문제(접속 후 생성으로 회피), 검증 대상과 파괴 타이밍 경합(파괴 단계 분리).
