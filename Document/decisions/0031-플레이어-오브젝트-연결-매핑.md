# 0031. 플레이어 오브젝트·연결 매핑

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 6 (플레이어 오브젝트·연결 매핑)

## 배경 (Context)

"이 연결의 아바타는 무엇인가"를 프레임워크가 몰라 모든 게임이 같은 상용구를 재작성했다 — 연결별 딕셔너리 관리, 퇴장 시 `FindObjectsByType` 전 씬 스캔 후 소유자 대조(Arena·LifecycleEventPlayTests가 정확히 이 패턴), 씬 스캔은 퇴장 이벤트(재배정 전 발화)와의 타이밍 계약까지 게임이 알아야 했다.

## 결정 (Decision)

`NetworkServer`에 게임 소유 선언적 매핑 추가 (ADR-0030과 짝):

1. **등록/조회** — `SetPlayerObject(connId, netId)`(netId 0 = 해제)·`ClearPlayerObject(connId)`·`GetPlayerObject(connId)`·`GetPlayerConnection(netId)`(역조회, 선형). 아바타 스폰 시 등록.
2. **자동 해제** — 연결 분리 시 매핑 자동 제거(재배정 정리와 같은 메인 큐 지점).
3. **퇴장 일괄 정리 헬퍼 2층** — Core `NetworkServer.DestroyObjectsOwnedBy(connId)`: 서버 측 엔트리에서 해당 연결 소유 **동적** 오브젝트만 네트워크 파괴(등록 해제·와이어·가시성 정리 — Core는 엔진 무의존이라 로컬 GO 파괴 불가). Unity `UniNetManager.DestroyObjectsOwnedBy(connId)`: Core 경로 위임 + 로컬 GameObject 파괴(NetworkDestroy) — **게임은 Unity 계층을 호출한다**. 씬 오브젝트는 파괴하지 않는다(레벨 가구 — 소유권은 재배정 정책에 위임). "재배정 전 발화" 계약 덕에 퇴장 이벤트에서 호출하면 퇴장자 소유가 정확히 식별된다.
4. **매핑 수명 순서** — 연결 분리 시 매핑 제거는 ClientDisconnected 이벤트 **발화 후**(finally 내 재배정 이후) — 핸들러 안에서 `GetPlayerObject(퇴장connId)`로 커스텀 정리(전리품 드롭 등) 가능.
5. **선언적 계약** — 매핑은 게임 선언이며 SetOwner 소유권 이전이 매핑을 이동시키지 않는다(이전된 아바타의 매핑은 게임이 재선언).

## 결과 (Consequences)

- **긍정**: 상용 상용구(내 아바타 찾기·퇴장 정리)의 프레임워크 제거 — 씬 스캔·타이밍 계약 지식이 게임에서 사라짐. Arena가 즉시 전환해 사용 예시.
- **부담 / 리스크**: 매핑은 게임 책임(미등록 시 조회 0 — 연결당 1 오브젝트 관례는 계약이지 강제 아님). 역조회는 선형(연결 수 수준 — 수천 연결에서 잦은 역조회 필요 시 역방향 사전 확장).
- **폐기 방법**: 없음(독립 API).
