# 0022. 사용자 가시 변경 시 소비자용 Skills 매뉴얼 동기화 규칙

- **상태**: 승인됨
- **날짜**: 2026-09-30
- **결정자**: 사용자 (프로젝트 소유자)
- **대체**: 없음 (신설 — [[0006-리뷰-품질-게이트-확대]]의 README 갱신 규칙과 병행)

## 배경 (Context)

- 2026-09-30 라이브러리 소비자용 AI 에이전트 매뉴얼 `skills/uninet/SKILL.md`를 신설했다 (표준 agent-skill 형식 — pi·Claude Code·Codex 호환).
- 그러나 "기능 변경 → 문서 반영" 규칙은 `Document/`와 `README.md`만 대상으로 하고, 스킬 파일은 동기화 체계 밖에 있다 — 기능이 바뀌면 스킬이 조용히 낡고, 소비자의 에이전트는 낡은 매뉴얼을 근거로 코드를 쓰게 된다.
- 한편 스킬은 소비자 관점 매뉴얼이라 내부 리팩토링·테스트·성능 튜닝은 내용과 무관하다. 전 기능 변경을 트리거로 삼으면 판단 비용만 늘고 오탐이 잦아진다.

## 결정 (Decision)

1. **AGENTS.md 핵심 원칙 1에 Skills 갱신 bullet 추가** — 사용자 가시 변경(공개 API 이름·시그니처, 동작 계약, `UNINET0xx` 진단, 런타임 로그, 설치 방법)이 있으면 같은 세션에서 `skills/uninet/SKILL.md`에 반영한다.
2. **트리거는 사용자 가시 변경만** — 내부 리팩토링·테스트·성능 튜닝은 스킬 내용에 영향이 없으면 제외. 불확실하면 기존 문서 규칙과 같이 사용자에게 이유를 보고한다.
3. **적용 지점은 AGENTS.md 한 곳** — doc-sync 절차 표·reviewer 검토 기준·doc-guard 훅 확장은 하지 않는다. [[harness]] 핵심 원칙에 동일 내용을 반영해 기록한다.

## 대안 검토 (Alternatives)

- **절차 3종 확장 (doc-sync 표 + reviewer 검토 기준 + doc-guard 훅)** — 가장 강력하지만 유지 지점 3곳이 늘고, 훅 수정은 코드 변경·`/reload`·오타(스킬 무관 변경) 처리 로직 비용이 따른다. AGENTS.md는 pi가 모든 세션에 자동 로드하므로 규칙 인지는 한 곳으로 충족된다고 판단해 기각.
- **규칙 없음 (수동 갱신)** — 스킬 낡음을 잡아낼 장치가 전혀 없어 기각.

## 결과 (Consequences)

- 규칙 인지는 AGENTS.md 자동 로드로 전 세션 적용된다. 갱신 강제는 기존 문서 규율(갱신 불가 시 사용자 보고·reviewer 검토)에 의존한다.
- 스킬이 문서 동기화 체계 안으로 들어왔다. 향후 스킬 파일이 늘어나거나 누락이 실측되면 doc-sync 표·훅 확장을 재검토한다.
