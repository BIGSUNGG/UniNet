# 0003. 기반 스택 패키지 참조 고정

- **상태**: 승인됨
- **날짜**: 2026-09-13
- **결정자**: 사용자 (프로젝트 소유자)

## 배경 (Context)

- DRPC·MessageProtocol·Communication 스택의 참조 방식이 구현 진입 차단 요소였다.
- 후보: 로컬 프로젝트 참조(수정 즉시 반영) / 패키지 고정 / 하이브리드.
- 하위 스택은 NuGet 패키지로 배포 중이다 (MessageProtocol 조사 시점 3.0.0, DRPC 3.1.0). Unity 쪽은 UPM이 NuGet을 직접 소비하지 못해 연결 방식이 필요하다.

## 결정 (Decision)

처음부터 **패키지 참조로 고정**한다. 로컬 프로젝트 참조는 스파이크 목적 외 금지.
.NET 계약·서버 로직은 NuGet 패키지, Unity 바인딩 쪽은 UPM 패키지로 소비한다.
UPM-NuGet 연결 방식(NuGetForUnity vs netstandard2.1 DLL 캡슐 UPM)은 Phase 0 스파이크에서 확정한다 ([[plan]]).

## 결과 (Consequences)

- **긍정**: 재현성·버전 명시·상용 배포 파이프라인이 처음부터 확립된다. "사용은 간단하게"의 소비자 경험과 일치.
- **부담/리스크**: 하위 스택 수정 시마다 패키지 배포 필요. 내부 NuGet 소스(로컬 패키지 소스)로 완화. UPM 연결 방식 미확정 상태.
- **완화**: 스파이크에서 연결 방식을 먼저 확정하고, 배포 절차를 각 DS_* 저장소와 합의한다.
- **폐기 방법**: 하이브리드(개발 중 프로젝트 참조)로 전환 시 이 ADR을 대체하고 [[plan]]·[[architecture]]를 갱신한다.
