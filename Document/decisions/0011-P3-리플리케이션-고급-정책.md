# 0011. P3 완결 — 리플리케이션 고급 정책 (가시성·우선순위·휴면·전송 주기·채널 예산)

- **상태**: 승인됨
- **날짜**: 2026-09-18
- **결정자**: DS + pi

## 배경 (Context)

- P3 로드맵(가시성·우선순위·Dormancy·NetUpdateFrequency·커스텀 NetSerialize·FastArray·채널 우선순위 큐) 중 **UniNet 저장소만 수정해서 구현 가능한 항목**을 구현한다 (사용자 결정 — 기반 스택 불변 원칙).
- **사용자 결정 — 범위 확정**: 커스텀 NetSerialize(MP 매핑)·FastArray(UniNet+MP 매핑)는 MessageProtocol 소스 수정이 필요하므로 **무조건 제외**(P4 이관, roadmap에 사유 표기). 채널 우선순위 큐는 우선순위 항목과 통합 구현으로 **포함**.
- 참조: UE 5.7 소스(Actor의 NetUpdateFrequency·NetPriority·NetCullDistance·ENetDormancy·IsNetRelevantFor·GetNetPriority).
- ADR-0009가 P3 재검토로 남긴 과제: 그룹별 마지막 전송 상태 추적(수신 그룹별 스냅샷 분리).

## 결정 (Decision)

1. **정책 인터페이스 — `IUniNetReplicationPolicy`** (`UniNet.Core.Hosting`):
   - 서버 틱이 오브젝트별 전송 여부·순서·주기를 읽는 단일 계약. `NetworkBehaviour`가 구현하며 사용자는 파생에서 가상 멤버를 재정의한다: `NetworkPriority`(UE NetPriority, 기본 1)·`NetworkUpdateFrequencyHz`(UE NetUpdateFrequency, 0=매 틱)·`NetworkCullDistance`(UE NetCullDistance, 0=미적용)·`NetworkDormant`+`FlushNetworkDormancy`(UE NetDormancy 단순화)·`IsNetworkRelevant(connId)`(UE IsNetRelevantFor, 기본 true).
   - 정책 속성은 코드 생성 대상이 아니다 — 런타임 프로퍼티로 제너레이터·와이어 포맷 무변경.
2. **틱 이중 모드**: `TickReplication(objects)` 1-arg = **즉시 모드**(주기·기아·예산 정책 미적용 — P2 호환·테스트·batchmode 검증기 경로 유지), `TickReplication(objects, time)` = **시간 모드**(드라이버가 `Time.unscaledTimeAsDouble` 제공). 시간 미제공 시 기존 동작이 100% 보존된다.
3. **가시성(Relevancy) 계약**:
   - 연결별 관련 판정 = 관련성 훅 AND (뷰어 위치 대비 거리 ≤ NetworkCullDistance). 뷰어 위치는 명시 API `SetViewerPosition(connId, x, y, z)`로만 제공 — **미설정 연결은 컬을 받지 않는다(페일오픈)**. 자동 추론(소유 오브젝트 위치 등)은 마법을 피해 게임에 위임한다(아레나 예시가 소유 플레이어 좌표를 주입).
   - **씬 오브젝트의 첫 평가는 조용히 시드만 한다** — P2의 "접속 후 등록 오브젝트는 변경분 델타만 전송" 계약을 유지.
   - **재진입(비관련→관련 복귀)과 동적 오브젝트 첫 평가는 기준선을 복구한다** — 동적은 스폰 메시지(클라에 없음), 씬은 서브별 전체 상태. 비관련 기간의 스냅샷 유실을 되돌린다.
   - 비관련 연결에는 델타·캐치업·스폰을 모두 보내지 않는다. 비관련 전환 시 클라는 마지막 상태를 유지한다 — **UE식 전파 파괴는 미지원**(씬 공유 오브젝트 모델과 충돌, 명시적 계약).
   - 어느 연결에도 비관련인 오브젝트는 델타 비교 자체를 생략한다(유휴 오브젝트 CPU 절감).
4. **우선순위·예산·기아 방지** (우선순위 + 채널 우선순위 큐 통합):
   - 전역 예산 `ReplicationBudgetPerTickBytes`(0=무제한 기본) + 유형별 예산 `SetReplicationChannelBudget(Type, bytes)`(채널=네트워크 유형별 대역폭 관리). 유형 예산 초과분만 연기되고 다른 유형은 계속 흐른다.
   - 델타 후보와 이전 틱 연기분을 **한 큐에서 병합**해 우선순위 순 전송. 기아 보정은 UE GetNetPriority 공식 `priority × (1 + 대기초/0.1)` — 대기가 길어질수록 낮은 우선순위도 결국 전송된다.
   - 연기된 항목은 `EnqueuedAt`을 보존해 기아 보정이 계속 성장한다. **예산보다 큰 단일 델타는 강제 전송**(size > budget) — 큰 델타가 영구 굶는 것을 방지.
   - 예산은 베스트에퍼트 셰이핑이다 — 관련 연결 수에 따라 실제 전송량이 예산을 다소 넘을 수 있다(하드 캡 아님, 명시적 계약).
5. **휴면(Dormancy) — 2상태 단순화**: `NetworkDormant`(bool) + `FlushNetworkDormancy()`. UE ENetDormancy 5상태 중 Awake/DormantAll에 해당. 휴면 중 델타 비교를 생략해 **스냅샷을 갱신하지 않는다** → 깨우면 휴면 중 누적 변경분이 한 번에 전송된다(엔진이 별도 큐를 갖지 않는 이유). 예산 초과로 이미 연기된 델타도 휴면 중에는 **보류**한다 — 드롭하면 스냅샷이 이미 갱신돼 변경분이 영구 유실되므로, 깨우면 보류분과 함께 전송된다.
6. **전송 주기(NetUpdateFrequency)**: 서브 단위 `NextReplicateTime` — 주기 미도달 틱은 비교를 생략하고, 도달 틱에 **최신 변경분만** 전송된다(중간값 유실 = 최신값 승 계약).
7. **ADR-0009 과제(그룹별 스냅샷 분리)는 유지·미재검토** — 가시성 전이의 기준선 전송이 OwnerOnly 유실 시나리오를 실질적으로 완화하고, 그룹별 스냅샷은 핫패스 비용을 2배로 만든다. 필요 시 별도 ADR로.

## 결과 (Consequences)

- **긍정**: P3 목표 중 UniNet 단독 구현 가능 항목 전부 완결 — UE 패리티의 핵심 스케줄링 축(누구에게·무엇 먼저·얼마나 자주·언제 멈추는가) 확보. 제너레이터·와이어 포맷·기반 스택 무변경. 즉시 모드로 기존 P2 동작·테스트 완전 보존.
- **부담 / 리스크**: 뷰어 위치는 게임이 명시 주입해야 한다(안 하면 컬 무효). 비관련 전환 시 클라 상태 고착(전파 파괴 없음). 예산 베스트에퍼트. 커스텀 NetSerialize·FastArray는 P4로 이관(MP 수정 필요).
- **폐기 방법**: 정책 인터페이스·가시성 계약 변경 시 새 ADR로 대체.

## 알려진 한계·후속 과제

- 커스텀 NetSerialize·FastArray — MP 소스 수정 필요(P4, roadmap 표기)
- 뷰어 위치 자동 동기화(클라→서버 뷰 전송 프로토콜) 미지원 — 게임이 소유 오브젝트 좌표를 주입하는 것이 계약
- 비관련 전환 시 클라 상태 고착 — 전파 파괴(UE DestroyAuto)는 미지원
- 관련 연결 수가 많으면 예산 초과 전송 발생(베스트에퍼트) — 연결별 예산은 후속 과제
