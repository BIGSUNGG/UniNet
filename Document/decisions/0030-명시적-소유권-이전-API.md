# 0030. 명시적 소유권 이전 API

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 5 (소유권 이전 API)

## 배경 (Context)

소유권은 스폰 시 명시 지정(`NetworkInstantiate(ownerConnId)`) 또는 고아 라운드로빈 배정만 가능했다 — 서버가 살아있는 오브젝트의 소유자를 다른 연결로 넘기는 API가 없어 아이템 줍기·탈것·점령 등 상용 필수 패턴을 게임이 우회해야 했다. `NetworkServer.ReassignOwnership`에 "production demands it" 자리표시 주석이 남아 있었다.

## 결정 (Decision)

`NetworkServer.SetOwner(netId, ownerConnId)` — 서버 권위 명시적 이전. 전 연결에 기존 OwnerUpdate 와이어(시스템 메시지 2)로 전파(ReassignOwnership과 동일 전파 범위 — 오브젝트를 갖지 않은 클라의 수신은 무해). 계약:

- **connId 0 = 방치(해제)**: 다음 재배정 패스(접속/해제 트리거)가 고아를 라운드로빈 입양. 생존하지 않는 connId도 재배정 시점에 해제로 귀결.
- **명시 소유권은 유지**: 기존 정책대로 생존 소유자의 오브젝트는 재배정 대상이 아니므로, 이전된 소유권은 조인/리브를 넘어 지속.
- 미지 netId → false. 와이어 신규 없음(ADR-0027/0029의 시스템 메시지 6/8과 달리 추가 프로토콜 없음).

## 결과 (Consequences)

- **긍정**: 상용 필수 패턴(줍기·탈것·점령·관전 이양)의 프레임워크 지원. 기존 와이어 재사용으로 제너레이터 변경 0. Arena가 K키 소유권 순환 데모로 사용 예시.
- **부담 / 리스크**: 전파 대상이 전 연결이라 대규모 세션에서 오브젝트 수 × 연결 수 만큼의 소유자 공지 트래픽이 생길 수 있다(기존 재배정 경로와 동일 — 개선 필요 시 관련 연결 한정 전파로 좁힌다). OwnerOnly 리플리케이션 수신 그룹이 즉시 전환되므로, 이전 직후 소유 클라는 다음 델타부터 OwnerOnly 필드를 받는다(캐치업 전송은 없음 — 이전 시점에 OwnerOnly 값이 달라졌다면 게임이 명시 갱신 필요).
- **폐기 방법**: 없음(독립 API). 전파 범위 최적화 시에도 공개 계약 유지.
