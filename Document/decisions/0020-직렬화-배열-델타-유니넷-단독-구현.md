# 0020. 직렬화 2종(커스텀 NetSerialize·FastArray)의 UniNet 단독 구현 전환

- **상태**: 승인됨 (2026-09-24 — 구현 완료로 승인 확정. 사용자 목표 계약 체결·구현·검증 완료)
- **날짜**: 2026-09-24
- **결정자**: (사용자 — /goal 계약 승인: 권고안 전부 수용·전체 게이트 검증·NetSerialize 선행 순차 구현)

## 배경 (Context)

[[roadmap]]의 유일한 잔여 과제 2종 — 커스텀 NetSerialize(QuantizedVector 상응)·FastArray(배열 델타)는 [[upstream-blockers]]에 "MessageProtocol 코덱 계층 수정 전제, UniNet 단독 구현 불가"로 기록되어 상류 저장소 세션 해결을 대기해 왔다.

2026-09-24 코드 검증 결과 이 전제는 현 구조와 일치하지 않음을 확인했다:

- 리플리케이션 페이로드의 직렬화 배선은 **UniNet 제너레이터가 필드 단위로 직접 생성**한다 (`Emitter.cs` `__UniNetWriteDelta`/`__UniNetWriteFull`/`__UniNetApplyIn` — 기본형은 writer 프리미티브 직접 호출, [Message]만 `MessageSerializer` 위임). MP 공용 코덱은 필드 타입에 따른 편의 경로일 뿐 필수 계층이 아니다
- 페이로드는 UniNet 소유 `byte[]`(마스크 헤더 + 값)이고 `SendReplicate`→`WriteBytes`로 MP/DRPC는 **순수 바이트 전송층**으로만 동작한다
- `MessageBufferWriter`/`MessageBufferReader` 프리미티브는 public이며 생성 코드가 이미 직접 호출 중 — 사용자 직렬화기도 같은 프리미티브로 쓸 수 있다
- 기존 "불가" 판정의 전제("코덱 등록 레지스트리가 MP에 없으면 호출할 대상이 없다")는 MP 네이티브 방식에만 성립하는 조건이었다

## 결정 (Decision)

직렬화 2종을 **MP 수정 없이 UniNet 단독으로 구현**한다.

- **커스텀 NetSerialize**: `[Replicated(Serializer = typeof(T))]` — 정적 `Write`/`Read` 쌍 계약을 UniNet 도메인에 정의하고 제너레이터가 해당 필드 배선을 직접 교체. 상세 설계 [[custom-netserialize]]
- **FastArray**: `T[]`/`List<T>` 필드의 요소 단위 옵 인코딩(인덱스-옵 방식)을 UniNet 와이어로 정의. `ReliableOrdered` 전달 전제로 시퀀싱 없이 리플레이. 상세 설계 [[fastarray-delta]]
- [[upstream-blockers]]의 MP 2건은 이 결정 승인 시 폐기(해결 경로 확정 표기)하고 [[roadmap]] 매핑을 MP → UniNet으로 갱신한다

## 결과 (Consequences)

- **긍정**:
  - 상류 의존 제거 — 즉시 착수 가능, ADR [[0003-패키지-참조-고정]] "상류 수정 없음" 원칙에 더 부합
  - 비교 연구([[research/network-framework-comparison]])가 지적한 유일 기능 열위(커스텀 직렬화·배열 델타 — 경쟁 6종 전부 보유) 해소 경로 확보
  - 부수 효과: 커스텀 직렬화기 지정 필드는 기본형·[Message] 외 타입(예: `Vector3`)도 허용 — Unity 타입 리플리케이션 해금
- **부담 / 리스크**:
  - 커스텀 직렬화 계약이 **UniNet 경로([Replicated] 필드)에만 유효** — 순수 MP `[Message]` 타입 내부 필드에는 미적용. MP 네이티브 코덱 등록 방식 대비 적용 범위가 좁다 (UniNet 스코프인 리플리케이션 대역폭 최적화에는 충분)
  - MP가 향후 공식 커스텀 코덱을 제공하면 UniNet 계약과의 이중 체계 가능 — 그 시점에 수렴 여지는 있으나 당면 필요 없음
  - FastArray는 제너레이터·생성 코드 복잡도 증가(중 규모) — diff 휴리스틱의 알려진 한계는 [[fastarray-delta]]에 명시
- **폐기 방법**:
  - 커스텀 NetSerialize: 필드에서 `Serializer` 옵션 제거 + 제너레이터 분기 제거 → 기존 MP 경로 복귀. 와이어는 기존 필드 포맷과 독립적이라 무영향
  - FastArray: 배열 필드 선언 제거 시 기존 스칼라 경로만 남음. 와이어 옵 인코딩은 새 필드에만 적용되므로 기존 호환 무영향
