# 0015. 연결 수명주기 이벤트 게이트웨이

- **상태**: 승인됨
- **날짜**: 2026-09-21
- **결정자**: 사용자 (게임 콜백 위임 방식 선택)

## 배경 (Context)

클라 연결 해제 시 게임 코드에 알림 경로가 없었다. `NetworkServer.DetachConnection`은 뷰어 상태 정리와 소유권 재배정만 수행 — 퇴장 플레이어의 아바타는 파괴되지 않고 다른 연결로 소유권만 재배정돼 좀비 오브젝트로 남았다. Arena 예제는 0.5초 폴링으로 "접속 수 − 플레이어 수" 잉여분을 간접 파괴했지만, 정밀한 연결-오브젝트 대응과 클라 측 세션 종료 인지가 모두 불가능했다.

대안:

1. **프레임워크 자동 파괴** — 해제 연결 소유 동적 오브젝트를 프레임워크가 즉시 파괴·전파. 편의성 높지만 소유 오브젝트를 게임이 뜻대로 남기지 못하고, 라운드로빈 최소 소유권 정책(명시적 "플레이어 소유" 개념 부재)과 충돌한다.
2. **게임 콜백 위임** — 프레임워크는 이벤트만 발화하고 처리는 게임이 결정.
3. 둘 다 (자동 파괴 옵션 플래그) — 두 경로 모두 구현·테스트 부담.

## 결정 (Decision)

**게임 콜백 위임을 채택한다.** 서버는 `NetworkServer.ClientConnected`/`ClientDisconnected`(`event Action<long>`, connId)를 메인 스레드에서 발화하고, 클라는 `UniNetManager.ClientDisconnected`(`event Action`)와 `IsClientConnected` 상태 조회를 제공한다. 오브젝트 처리(아바타 파괴 등)는 게임 콜백이 결정한다.

발화 순서 계약:

- 해제 — 상태 정리 → **이벤트 발화** → 소유권 재배정 (게임이 재배정 전에 소유자로 오브젝트를 식별할 수 있게)
- 접속 — 환영 → 소유권 배정 → 캐치업 → **이벤트 발화** (이후 스폰과 캐치업 충돌 없음)

구독자 예외는 격리한다(첫 예외가 나머지 구독자를 묻지 않음). 마지막 예외는 원본 스택 트레이스를 보존해 재던져 드라이버의 메인 펌프 보호가 로그하고, 펌프 잔여 작업은 다음 프레임에 재개된다. 재던짐이 같은 액션의 잔여 문장을 건너뛰지 않게 해제 경로의 소유권 재배정은 `finally`로 보장한다 — 구독자 예외와 무관하게 재배정은 항상 실행된다 (리뷰 라운드 1에서 보강). 클라 플래그는 허브 구독 직후 확정하고 허브 동일성 필터로 이전 세션 허브의 지연 관측분을 무시한다 — 자발 `ClientStop`은 상태만 해제하고 이벤트는 발화하지 않는다.

## 결과 (Consequences)

- **긍정**: 라운드로빈 소유권 정책과 무충돌. 퇴장 아바타 정밀 파괴로 좀비 오브젝트 소멸. 클라 재접속 UX 구현 가능. Arena 예제가 폴링 보조에서 이벤트 주도로 정밀화.
- **부담 / 리스크**: 게임이 이벤트를 구독하지 않으면 여전히 좀비가 남는다 (폴링 백업은 게임 책임 — Arena는 둘 다 유지). 이벤트 핸들러 예외는 펌프 잔여 작업을 다음 프레임으로 미루되 소유권 재배정은 `finally`로 즉시 보장된다. 접속·해제 churn이 크면 콜백 비용이 연결 수에 비례한다.
- **폐기 방법**: 자동 파괴 정책이 필요해지면 정책 인터페이스(예: `IUniNetDisconnectPolicy`)로 확장하는 새 ADR로 대체.
