# 0019. 코드 주석 영어화와 사용자 관점 규약

- **상태**: 승인됨
- **날짜**: 2026-09-22
- **결정자**: 사용자 지시

## 배경 (Context)

- 저장소 코드 주석이 한국어·영어 혼용이었고, 언어 규약 자체가 정의돼 있지 않았다. 기존 규약([[conventions]])은 "모든 문서는 한국어(코드·기술 용어는 영어)"로 Document/ 대상이며 코드 주석을 다루지 않았다.
- UniNet은 상용 라이브러리로서 공개 API의 XML doc(`///`)이 IntelliSense·문서 생성기를 통해 **라이브러리 사용자(Unity 게임 개발자)에게 직접 노출**된다. 기존 주석 일부는 구현자 관점(내부 흐름 서술)이라 사용자가 알아야 할 계약(실행 주체·기본값·제약·호출 시점)이 불분명한 곳이 있었다.
- 대안: ① 한국어 주석 유지 + 관점만 개선 ② 영어 전환만 ③ 영어 전환 + 사용자 관점 재작성.

## 결정 (Decision)

1. **모든 코드 주석( `//` · `///` · `/* */` )은 영어로 쓴다.**
2. **공개 API XML doc은 라이브러리 사용자 관점**으로 쓴다 — 첫 문장에 무엇인지/무엇을 하는지, 이어서 사용자가 알아야 할 것만(실행 주체 server/client/host, 기본값, 제약, 호출 시점, 소유권·보안 동작). 시그니처가 이미 말하는 것의 반복과 내부 구현 서술은 하지 않는다.
3. **인라인 주석은 why 중심** — 의도·프로토콜 이유·불변식·성능 노트. 코드가 말하는 what의 반복은 쓰지 않는다(없는 것보다 나쁘다).
4. **적용 범위는 저장소 전체**(Package·CodeGenerator·Sandbox 예제·테스트). 제너레이터가 생성 코드에 방출하는 주석 템플릿(`Emitter.cs`)도 영어로 한다.
5. **문자열 리터럴은 주석이 아니다** — `Debug.Log`·예외 메시지 등은 이 결정의 대상이 아니며 별도 결정까지 현행 유지.
6. 2026-09-22 저장소 전체 일괄 적용 완료(78개 파일, 코드 로직·식별자 무변경).

## 결과 (Consequences)

- **긍정**: IntelliSense·생성 문서가 영어로 표기되어 국제 사용자 접근성 향상. 사용자 관점 재작성으로 주석-코드 대조 리뷰가 쉬워지고 잘못된 주석(코드와 불일치)이 드러난다.
- **부담 / 리스크**: Document/(한국어)와 코드 주석(영어)의 언어 분리가 유지된다 — 이는 의도된 것(문서는 팀 참조, 주석은 라이브러리 소비자 참조). 사용자 대면 로그 문자열이 여전히 한국어인 것은 후속 결정 과제로 남는다.
- **폐기 방법**: 본 ADR을 대체하는 새 ADR에서 언어·관점을 다시 정의하고 주석을 재작성한다.
