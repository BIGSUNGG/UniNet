# 0034. 재접속 세션 보존+재부착

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 9 (재접속 세션 보존+재부착)

## 배경 (Context)

모바일 순단(와이파이↔셀룰러)·일시 유실은 상용 게임에서 일상이다. 기존 동작은 연결 해제 시 즉시 소유권 재배정 — 재접속하면 완전 신규 접속으로, 이전 오브젝트 소유권을 잃는다. 실사용 갭 검토 치명 ①: "재접속·세션 복구가 프레임워크 차원에서 불가능".

## 결정 (Decision)

1. **세션 토큰** — 서버가 접속마다 고유 토큰(증가 ulong)을 발급해 Welcome에 실어 보낸다. 클라는 `NetworkClient.SessionToken`으로 보관.
2. **유예 세션** — `NetworkServer.SessionGraceSeconds`(기본 0=비활성, 게임이 설정). 연결 해제 시 소유 오브젝트 목록+플레이어 매핑을 토큰 키 유예 세션으로 보존. `ReassignOwnership`은 유예 중 소유자를 건너뛴다(소유권이 재배정되지 않고 대기). 드라이버 Update가 `SweepGraceSessions`를 호출해 만료된 세션을 정리하고 고아 재배정을 실행.
3. **재부착** — 클라 재접속 시 생성 허브가 자동으로 토큰을 실은 ResumeRequest(와이어 10)를 전송. 서버 핸들러가 메인 큐에서 `ResumeSession(token, newConnId)` 호출 — 유예 세션의 소유 오브젝트를 새 connId로 이전하고 OwnerUpdate 전파·플레이어 매핑 복원.
4. **클라 API** — `UniNetManager.ReconnectAsync(address, port, options)` — 이전 세션 토큰을 보존한 ClientAsync 재호출. `ClientAsync` 자체도 토큰을 이전 세션에서 계승하므로, 일반 ClientAsync 재호출도 자동 재개 시도.

## 결과 (Consequences)

- **긍정**: 모바일 순단·일시 유실에서 소유권·아바타 보존. 게임 코드는 ReconnectAsync 호출만으로 복구 — 토큰·와이어·재부착은 프레임워크 내부.
- **부담 / 리스크**: 유예 중 오브젝트는 소유자가 "죽은 연결"로 표시 — 다른 클라가 해당 오브젝트의 OwnerOnly 델타를 못 받는다(재부착 또는 만료 시 해소). 토큰 위조 시 다른 플레이어 세션 가로채기 가능 — 실배포에서는 연결 키 인증과 결합 필요(토큰은 연결 키 내에서만 유효). 유예 시간 동안 서버 메모리에 세션 보존(오브젝트 목록 수준 — 미미).
- **빠른 재접속 경합**: 클라가 서버의 연결 죽음 감지(하트비트 타임아웃 기본 ~5s) 전에 재접속하면 유예 세션이 아직 없어 ResumeRequest가 실패할 수 있다(모바일 와이파이↔셀룰러 전환 <2s에서 발생 가능). resume 성공/실패의 클라 통보 응답도 없어 게임은 소유권 폴링으로 판별. 감지 지연 창 보완(살아 있는 연결 토큰 일치 폴백)은 후속 확장 포인트.
- **폐기 방법**: SessionGraceSeconds = 0 (기본값) — 즉시 재배정·기존 동작.
