# ADR-0052 — 종료·실패·재시작 경로의 대칭 정리와 등록 세대

- 상태: 채택 (2026-10-22)
- 관련: ADR-0027(정지 그레이스), ADR-0034(유예 세션), ADR-0046(자발 퇴장), LIF-001(감사 항목)
- 버전: 0.19.0

## 배경

세 개의 생명주기 결함이 상호 결합되어 있었다:

1. **ServerStopAsync 무스윕** — 동기 `ServerStop`은 `SweepDynamicSpawns()`로 동적 스폰 원본을 파괴했지만 async 버전은 누락. 정지된 서버의 동적 객체는 서버가 배부한 netId를 캐시한 채 잔존 → 동일 프로세스 재시작 시 재활용 netId와 충돌.
2. **ServerAsync 시작 실패 무롤백** — `SetServer`+환경 등록이 listen 대기 이전에 실행되고 try/catch 부재 → 포트 점유 등으로 listen이 실패하면 좀비 서버가 환경에 잔존(`IsServer` true, 드라이버 틱 지속).
3. **등록 플래그 비가역** — `NetworkBehaviour`의 `_registeredServer/_registeredClient` 불리언은 리셋 경로가 전무. 정지→재시작 후 씬 객체들이 새 서버 인스턴스에 **조용히 재등록되지 않음**(스폰 누락·RPC 무응답으로 열화).

## 결정

1. **ServerStopAsync도 스윕한다**(동기 ServerStop과 동일 위치 — DisposeAsync 뒤). 메인 스레드 전제(FindObjectsByType)는 기존 정지 경로 계약과 동일.
2. **ServerAsync listen을 try/catch로 감싸 실패 시 `SetServer(null)` 후 재던진다.** 롤백은 환경 탈착만 — 드라이버 GameObject는 재시작 재사용.
3. **등록 추적을 불리언에서 세대 스탬프 비교로 교체한다**: `NetworkServer.Generation`(static Interlocked 카운터, 서버 인스턴스별 스탬프)·`NetworkClient.Generation`(동일 — 전용 클라 프로세스용), `NetworkBehaviour`의 `_registeredServerGen/_registeredClientGen`(0=미등록). 스킵 조건은 "현재 인스턴스 세대와 일치" — 새 인스턴스(세대 증가)마다 모든 객체가 재등록 대상이 되고, 같은 세대 내 재호출은 멱등. (기각: 정지·실패 경로에서 플래그 리셋 — 모든 교체 경로를 호출자가 기억해야 함; 인스턴스 강참조 저장 — 죽은 서버 레지스트리를 씬 객체 수만큼 GC 고정)
4. **클라 세대 패리티 포함** — StopAsync→HostAsync 재시작이 서버·클라 양쪽 생성을 포함하므로 동일 근원 결함을 한 번에 봉쇄. 전용 클라 프로세스는 서버 세대가 항상 0(센티널)이므로 `NetworkClient.Generation`이 클라 등록의 비교 소스가 된다.
5. **IVT 제약으로 세대 노출은 public**(UniNet.Core의 InternalsVisibleTo는 테스트 어셈블리만 — NetworkClient.CountFaultedPayload 선례와 동일).

## 기각한 대안

- **호출자 책임 스윕**: 대칭성이 결함 정의 자체.
- **정지 경로 플래그 리셋**: 이중 시작·실패 재시도 등 모든 교체 경로 누락 위험.
- **예외 기반 거부**: static 초기화 중 throw는 어셈블리 로드 전체를 깨는 과잉.

## 결정 2 — 스윕 게이트 (r26 I-1, 같은 릴리스)

ServerStopAsync의 XML 계약("no-op when not listening")이 무조건 스윕과 모순되는 문제: 클라 전용 프로세스(리슨 부재)에서 ServerStopAsync를 호출하면 스윕이 **클라 미러**를 파괴한다. 수정: 스윕을 `server != null || handle != null`(이번 호출이 실제 정지였을 때만)으로 게이트 — 재호출 시 재위생 불변, 클라 전용 오염 원천 차단. 계약 문장이 다시 참이 된다.

## 결과

- 사용자 가시 동작 개선: **재시작 후 씬 객체가 자동 재등록**된다(기존엔 조용히 누락). ServerStopAsync 후 고스트 동적 객체가 남지 않는다. ServerAsync 실패 시 환경이 깨끗이 롤백된다.
- 세대 값은 와이어로 전송되지 않는다(런타임 내부 관측 전용) — 프로토콜 불변.
- 주의: ServerStopAsync의 스윕은 메인 스레드에서 호출해야 한다(기존 정지 경로 계약과 동일).
