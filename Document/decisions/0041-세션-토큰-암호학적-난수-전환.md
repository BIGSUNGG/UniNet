# 0041. 세션 토큰 암호학적 난수 전환

- **상태**: 승인됨 (구현 — 2026-10-19)
- **날짜**: 2026-10-19
- **결정자**: 상용 넷코드 사전 검증 SEC-001 (작업 지시 — 사용자 승인 방향)

## 배경 (Context)

ADR-0034의 재접속 세션 보존은 접속마다 "고유 토큰"을 발급해 Welcome에 실어 보내고, 재접속 시 이를 bearer 토큰처럼 제시하면 유예 세션(소유 오브젝트·플레이어 매핑)을 새 연결로 재부착한다.

기존 구현은 `시드(틱카운트+Random) 뒤 +1` 증가 `ulong`이었다. 실제 Unity 실행에서 인접 발급값으로 다음 토큰을 예측할 수 있음이 확인되었다(SEC-001, 탐침 기록 `.pi-subagents/artifacts/commercial-netcode/baseline/security-token-probe.jsonl` — 비밀 값 미출력). 같은 서버에 접속한 악성 플레이어가 이웃 토큰을 추측해 `ResumeSession`을 호출하면 피해자의 유예 세션 소유권을 탈취할 수 있었다. 부수 결함: `ResumeSession`은 유효 토큰이면 어떤 새 connId(존재하지 않거나 죽은 연결 포함)든 검증 없이 세션을 소비·이전했고(공격자는 추측 토큰 + 자기 연결 ID로 곧바로 탈취), 만료된 세션은 제거했다(미지 token은 원래 소비하지 않았다). 재개 요청 페이로드는 파싱 전 크기 상한이 없었고, 디버거가 토큰 원문을 표시했다.

## 결정 (Decision)

1. **토큰 형식** — 발급 토큰은 `System.Security.Cryptography.RandomNumberGenerator` 256비트(32바이트) 난수의 opaque Base64 문자열(44자, `NetworkServer.MaxSessionTokenChars`). 시간·`Random`·증가값·`Guid` 금지. 발급 토큰은 비지 않고 활성 연결·유예 세션 토큰과 충돌하지 않는다(충돌 확률 ~2^-256, 재발급 루프는 벨트 앤 브레이스). **비활성 = 빈 문자열**(null 포함)로 문서화 — 재개 요청도 발급 토큰도 아님.
2. **와이어** — Welcome(와이어 1)·ResumeRequest(와이어 10)의 토큰 필드를 `string`으로 변경. 생성 허브의 ResumeRequest 수신은 **파싱 전** 페이로드 상한(int32 UTF8 길이 접두 4바이트 + 토큰 44자 = `MaxResumeRequestPayloadBytes` 48바이트) 검사로 고정 형식 계약을 적용한다. MessageProtocol 문자열 판독은 선언 길이를 버퍼와 대조한 뒤에야 슬라이스하므로 위조 접두는 대형 할당이 아니라 예외가 되고, 상한 초과·불량 입력은 조용히 폐기한다(미인증 경로 — 메시지마다 예외를 기록하면 공격자가 콘솔을 폭격하는 수단이 된다. 수신 바이트 카운터는 계속 관측). 타입·와이어 변경이므로 패키지 0.4.0 — ADR-0028 핸드셰이크로 혼속 거부는 **기본 ProtocolVersion(패키지 버전 비교)을 쓸 때** 성립한다. 사용자 정의 `ProtocolVersion`(Arena 등)은 앱 식별자만 비교하므로 wire/API가 달라지는 배포에서는 앱 식별자를 양단 함께 올려야 한다(이번 배포에서 Arena는 `arena-1` → `arena-2-uninet-0.4`로 상향 — SEC-001 와이어 변경의 필수 마이그레이션). wire 버전 자체의 독립 검증은 CON-001 전체 목표에 남는다. 제너레이터 0.2.8.
3. **재개 검증** — `ResumeSession(token, newConnId)`는 (a) 토큰이 살아 있는 유예 세션과 일치, (b) 만료 전, (c) `newConnId`가 현재 살아 있는 연결 — 세 조건을 모두 통과할 때만 세션을 소비·이전한다. 잘못된/추측/만료/미발급 토큰이나 임의·죽은 connId는 **거부만 하고 세션을 소진하지 않는다**. 만료 세션의 제거·고아 재배정은 기존 `SweepGraceSessions`(0.5s 주기)가 담당한다.
4. **스레드 경계** — 토큰 발급은 전송 스레드(AttachConnection)에서, 유예 저장·재개·소거는 메인 큐에서 실행된다. `_graceSessions` 레지스트리 접근을 전부 `_gate`(재진입 가능한 연결 레지스트리 락)로 통일해 경합을 제거한다. 과거 토큰 전체 목록 같은 무한 증가 구조는 만들지 않는다.
5. **비밀 취급** — 토큰 원문은 로그·예외 메시지에 넣지 않는다. 에디터 디버거는 존재 표시(`issued (44 ch)` / `none`)로 마스킹한다. 상한 위반 예외는 사유만 기록한다.

## 결과 (Consequences)

- **긍정**: 인접 토큰 예측·토큰 추측으로 타인 유예 세션 탈취 불가(256비트 엔트로피). 공격자의 재개 시도 폭격으로 피해자의 유예 창이 소진되지 않는다. 재개 파싱의 할당이 상한으로 봉쇄된다.
- **부담 / 리스크**: `ulong` 토큰을 저장하던 게임 코드는 `string`(빈 = 없음)으로 마이그레이션 필요(0.4.0 파괴적 변경). 토큰은 연결 키 인증과 결합하면 더 강력하나(ADR-0034 부담 사항) 이번 범위 밖 — CON-002 접속 승인 확장점 과제로 유지.
- **미구현(명시적 유지)**: 살아 있는 기존 연결의 빠른 재개 폴백·재개 승인/거절 결과 응답·게임 아바타 완전 복구는 REC-001에, 연결 승인 확장점(자격 증명 검사)은 CON-002에 남아 있다(퇴장 정리×grace 상호작용 포함). 둘 다 **이번 SEC-001 배포 단위의 범위 밖이지만 전체 상용 목표에는 남아 있는 과제**다.
- **폐기 방법**: `SessionGraceSeconds = 0`(기본값) — 유예 자체가 비활성.

## 검증

- EditMode `ReconnectGraceTests` 8종 — 기존 4종(보존·재부착·만료·비활성) 갱신 + 신규 4종: 토큰 형식/길이/다중 발급 유일성, 추측 토큰으로 피해자 소유권 유지, 잘못된 connId 거절 후 올바른 연결 재개(토큰 미소진), 중복 재개(토큰 재생) 거부.
- EditMode `ResumeRequestWireTests` 2종 — 실제 MessageBufferWriter 페이로드(48바이트)를 생성 서버 허브 `__ResumeRequest_Requested`(reflection)로 투입해 PumpMain까지 수행: 정상 요청 재개 성립, 잘림·초과(49바이트)·위조 접두(100만 자 선언)는 세션·소유권 불변·할당 폭발 없음·이후 정상 재개 성공. 검토 r1이 지적한 “정상 와이어 요청이 항상 거절되는 버그를 core-direct 테스트가 못 잡음” 계층을 막는다.
- Arena 에디터 진단 `ArenaBootstrap → Diag/SEC-001 위조 토큰 재개 거부 (기존 세션 정지 후)` — 진입 시 기존 데모 런타임을 명시적으로 정상 정지(재진입 가드 포함)하고, 소유 대상은 **비동적 마커**(실제 서버 레지스트리 등록 — ClientStop의 동적 스폰 소거가 아바타를 파괴하는 기존 LIF/REC 갭을 피함)로 실서버/클라 API로 위조 거부·피해자 소유권 유지·진짜 토큰 재부착·플레이어 매핑 복원을 확인(토큰 원문 미출력). **마커 기반 소유권·재개 검증이며 실제 Unity 아바타 복구 검증이 아니다.**
- 실행 검증·리뷰·배포는 부모 단계에서 수행 후 audit SEC-001 판정 갱신.
