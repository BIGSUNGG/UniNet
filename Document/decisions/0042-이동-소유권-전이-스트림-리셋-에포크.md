# 0042. 이동 소유권 전이 스트림 리셋·에포크

- **상태**: 승인됨
- **날짜**: 2026-10-20
- **결정자**: 사용자 승인 방향(부모 확정 설계) · worker 구현

## 배경 (Context)

`MoveSimulation.AdoptInput`의 재생 가드(`seq <= _lastSeenSeq` 기각)는 임기(tenure)를 모른다. 소유권 이전(ADR-0030 SetOwner·재배정 입양·ADR-0034 세션 재부착)이 일어나도 서버와 새 소유자의 입력·예측 상태를 교체하는 경로가 없어 두 가지 반례가 확인됐다(상용 넷코드 점검 MOV-001, 실행 반례 `mov001-pre-fix-probe{,-2}.json`).

1. **probe-1** — 기존 `OnTeleport` 리셋 후 새 소유자의 seq 1이 구 seq 900 이하로 기각돼 무기한(구 최대 시퀀스 도달 전까지) 막힌다. `OnTeleport`는 상태·큐·히스토리만 지우고 `_lastSeenSeq`/`LastAdoptedSeq`를 지우지 않는다.
2. **probe-2** — 이상적으로 스트림을 리셋해도(`_lastSeenSeq=0`) 이전 임기의 전송 중 패킷 seq 900이 먼저 도착해 채택되고 새 스트림(seq 1)이 다시 오염된다. 생성기의 ServerRpc 소유자 게이트(ADR-0016)는 "현재 소유자"만 검사하므로 A→B→A 복귀 후 A의 구 임기 패킷은 통과한다.

클라 측에서도 `NetworkClient.ApplyOwner`는 소유자 캐시만 갱신할 뿐 이벤트가 없어, 폴링(IsOwner)은 프레임 경계에서만 변화를 보고 same-frame 전이를 구조적으로 놓친다.

## 결정 (Decision)

1. **`NetworkClient.OwnershipChanged(netId, prev, next)`** — Core C# 이벤트. `ApplyOwner`가 **값이 실제로 바뀔 때만** 발화한다(첫 배정은 기준선이므로 미발화, 동일값 재전파 무시 — `SetOwner` 재호출·기준선 재전송 필터). 발화는 DRPC 디스패치 스레드 — 구독자는 `UniNetEnvironment.QueueOnMain`으로 마셜해야 하고, 미등록 netId 통보도 오므로 로컬 조회 후 널가드한다. Core→Unity 역의존 없음.
2. **`INetworkMoveSimulation.ResetOwnershipStream()`** — 소유권 임기 경계 리셋. 서버 입력 큐·소유 클라 히스토리·`_lastSeenSeq`·`LastAdoptedSeq`를 지우되 **권위 게임 상태 TState와 최신 입력은 보존**한다. `OnTeleport`와의 계약 차이: 텔레포트는 상태도 리셋(점프 궤적 미재개), 소유권 전이는 상태를 이어받아 권위가 끊김 없이 계속된다.
3. **이동 소유권 epoch** — `NetworkTransform`에 서버 권위 `[Replicated(OwnerOnly, Notify)] uint _moveEpoch`. 서버는 매 프레임 소유자 값을 관측하며 **임기→임기 이전**(직접 이전 또는 해제 — 이전 관측 소유자가 0이 아닌 값 변경)에서만 epoch를 증가시키고 리셋과 짝 실행한다. **0→비0 입양은 베이스라인이다(무범프·무리셋)**: 초기 스폰은 스트림이 처녀상태고, 해제 후 입양은 해제 시점의 범프+리셋이 이미 경계를 막았으며 0 소유 기간엔 소유권 게이트가 유효 발신자를 차단한다. 이 규칙은 타이밍 독립적이다 — 소유 연결 attach가 인스턴스 첫 Update보다 늦어도 초기 입양이 범프하지 않는다. 이동 입력 봉투 `UniNetBlobEnvelope.Data`에 클라 epoch 접두를 추가한다: `[uint epoch][int length][byte[] 입력]` (MessageProtocol 표준 코덱). **생성 RPC 시그니처·와이어 시스템 메시지는 불변** — 접두는 봉투 내부이므로 생성기 재빌드가 필요 없다(복제 델타 레이아웃은 필드 추가로 변경 — 버전 핸드셰이크가 보호). 서버는 epoch 불일치 입력을 조용히 기각하고 `NetworkTransform.MoveEpochMismatches` 카운터로만 관측한다. 클라는 소유권 획득 이벤트와 OwnerOnly epoch 수신 **양경로**에서 자기 세션을 재바인딩한다(`_clientSeq=0`·accumulator·히스토리 클리어·권위 좌표 재앵커). 예측 상태는 첫 ack 롤백으로 수렴한다(하드 스냅 포함). 호스트(권위 인스턴스)는 이벤트 재설정을 스킵해 이중 리셋을 방지한다.

## 결과 (Consequences)

- **긍정**:
  - 소유권 이전 후 새 소유자의 스트림이 즉시 채택되고 ack가 재개된다(Arena 실RUDP 진단으로 단언).
  - 이전 임기의 전송 중 패킷이 현재 소유자 게이트를 통과해도 epoch 게이트에서 기각된다(probe-2 폐쇄).
  - 소유권 변화가 게임 코드에 관측 가능해진다(값변경 전용 이벤트 — UI·사운드·로컬 권위 전환 훅).
  - 서버 권위 TState 보존으로 전이 전후 이동이 연속된다(속도·쿨다운 등).
- **부담 / 리스크**:
  - **파괴 변경 2종**: `INetworkMoveSimulation` 구현자는 `ResetOwnershipStream`을 추가 구현해야 하고, 봉투 레이아웃을 직접 다루는 커스텀 이동 경로는 epoch 접두를 반영해야 한다(마이그레이션 — Package/CHANGELOG 0.5.0). 입장당 8바이트(에포크+길이) 증가.
  - **전이 잡음**: 새 소유자가 OwnerOnly epoch 델타를 받기 전 보내는 입력은 구/스테일 epoch로 기각된다(연속 소유자는 ~1 복제 틱, 입양 직후 첫 소유자는 epoch 캐시가 없어 정지 재전송이 전달할 때까지 최대 ~0.25s). 자가치유 — epoch 도착과 동시에 세션이 재동기화된다(놓친 소유권 이벤트의 백스톱이기도 하다).
  - **문서화 한계(천장)**: 서버 관측은 프레임 단위라 한 프레임 안에서 A→B→A가 완결되면 범프가 없다. 이 경우 새 스트림이 구 최대 시퀀스를 넘어설 때까지(60Hz에서 최대 ~초 단위) 채택이 지연된 뒤 자가치유된다 — 병리적 게임코드 패턴(동일 객체에 같은 프레임 내 이중 SetOwner)이며, 회피가 필요하면 게임이 전이를 프레임 경계로 분산해야 한다.
  - OwnerOnly epoch 델타는 Unreliable로 전송되나 정지 재전송(ADR-0039)이 최종 수신을 보장한다.
- **폐기 방법**: epoch 필드·봉투 접두·이벤트를 제거하고 `ResetOwnershipStream`을 `OnTeleport`로 되돌리면 이전 동작(전이 후 스트림 봉쇄)으로 복귀한다. 관련 문서·버전을 되돌려야 한다.
