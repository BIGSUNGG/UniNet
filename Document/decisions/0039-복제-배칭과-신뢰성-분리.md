# 0039. 복제 배칭과 오브젝트별 전송 신뢰성 분리

- **상태**: 승인됨
- **날짜**: 2026-10-13
- **결정자**: 사용자 + pi (아레나 데모 메시지 수 과다 원인 분석에 따름)

## 배경 (Context)

아레나 데모에서 서버→클라 메시지 수가 과다했다. 원인 분석 결과 (1) 복제 주기 조절 미사용으로 시뮬 레이트(60Hz)마다 즉시 전송, (2) 모든 복제 델타가 `ReliableOrdered`로 나가 신뢰 패킷마다 RUDP ACK가 왕복, (3) 배칭 부재로 델타 1개 × 커넥션 1개 = 데이터그램 1개, (4) 클라 수에 비례한 배수 증가가 겹쳤다. 2인 아레나 기준 서버 송신이 정지 시 ~120 msg/s, 이동 시 ~240+ msg/s였다.

또한 이동 스트림 같은 고빈도 상태는 신뢰 전송이 불필요하다 — 다음 델타가 이전 델타를 대체하기 때문. 그러나 단순히 비신뢰로 바꾸면 **마지막 델타 유실 시 클라가 옛 상태에 영구 정지**하는 구멍이 남는다 (멈춘 오브젝트는 뒤따르는 델타가 없음).

대안 검토: (a) 주기 keepalive 전체 재전송 — 멈춘 오브젝트도 계속 재전송해 절감 효과를 상쇄, (b) 필드별 신뢰성 — 직렬화 계약이 복잡해짐, (c) 유실 리스크 인정 — 게임 품질 문제. 채택안: 오브젝트 단위 신뢰성 정책 + 정지 시 신뢰 재전송(quiescence resend) + 신뢰성별 배칭.

## 결정 (Decision)

1. **오브젝트별 복제 신뢰성 정책** — `NetworkBehaviour.NetworkReplicationDelivery` (`Delivery.ReliableOrdered` 기본 / `Unreliable`). `Unreliable`은 와이어에서 `Sequenced`(유실 허용·순서 보장)로 나간다 — 위치 스트림의 순서 뒤바뀜은 보간 버퍼를 오염시키므로 순서는 유지한다. 스폰·캐치업·OwnerUpdate 등 기존 신뢰 경로는 그대로 유지.
2. **정지 시 신뢰 재전송** — `Unreliable` 오브젝트가 마지막 델타 후 `QuiescenceResendDelaySeconds`(0.25s) 이상 조용해지면 현재 풀 상태를 신뢰 배치로 1회 재전송하고 조용한 구간당 1회만 반복한다. 이동 중 유실은 다음 델타(~16ms)가 덮고, 멈춘 뒤 유실은 이 재전송이 복구한다.
3. **휴면 플러시 신뢰 강제** — `FlushNetworkDormancy`는 깨어난 첫 델타를 신뢰 배치로 강제한다(`MarkNextSendReliable`). 플러시 델타가 유실되면 오브젝트가 잠긴 채로 남는 최악의 경우를 원천 차단.
4. **신뢰성별 틱 배칭 (wire 13)** — 복제 틱은 커넥션별로 델타를 신뢰/비신뢰 각각 1개의 배치 메시지로 묶어 보낸다(틱당 최대 2메시지). 배치 페이로드는 `count + (netId, subId, methodId, length, payload)*` 형식이며, 수신측은 전역 `UniNetBatchRegistry`(methodId→applier)로 라우팅해 어떤 어셈블리가 수신하더라도 모든 등록 타입을 적용한다. 배치 상한 1000B(Sequenced는 단편화 불가 — MTU 보호).
5. **버전 상향** — 와이어 포맷이 바뀌므로 `UniNetInfo.Version` 0.3.0으로 상향 (ADR-0028 핸드셰이크가 구버전 혼속을 거부).

Arena 데모는 `NetworkUpdateFrequencyHz = 30`(NetworkTransform·ArenaPlayer 슬롯 모두)을 함께 설정한다 — 60Hz 시뮬의 스텝 2개가 델타 1개로 병합된다.

## 결과 (Consequences)

- **긍정**: 2인 아레나 기준 서버 송신 메시지가 이동 시 ~240 msg/s → 틱당 오브젝트 수와 무관하게 커넥션당 최대 2개(≈120 msg/s에서 신뢰 ACK 없는 스트림 분리)로 감소. 이동 스트림의 ACK 왕복 제거. 와이어는 하위 호환 없이 버전 게이트로 보호.
- **부담 / 리스크**: 비신뢰 오브젝트의 최종 상태 복구가 최대 0.25s 지연될 수 있다(이동 재개 시 즉시 덮임). 비신뢰 배치 유실 시 같은 배치의 다른 엔트리도 함께 유실된다(모두 고빈도 상태라 허용). 배치 포맷은 UniNet 내부 계약 — 버전 게이트로 보호.
- **폐기 방법**: `NetworkReplicationDelivery`를 기본값으로 되돌리고 TickReplication의 배치 경로를 개별 `SendReplicate`로 되돌리면 P2-호환 즉시 모드로 복귀한다. wire 13은 미사용 id로 남는다.
