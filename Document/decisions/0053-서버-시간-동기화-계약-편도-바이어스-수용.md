# ADR-0053 — 서버 시간 동기화 계약: 편도 바이어스 수용, 보정은 게이트 (TIM-001)

- 상태: 채택 (2026-10-22)
- 관련: 와이어 5(TimeSync), RTT 에코(와이어 9), NetworkTransform 보간, TIM-001(감사 항목)
- 버전: 0.20.0 (코드 로직 무변경 — 계약 문서화+측정 테스트)

## 배경

감사 항목 TIM-001이 "ApplyServerTime의 편도 지연 보정 부재 + 감소 보정/단조 클램프로 시간 진행 정지 가능성"을 제기. 분석 결과:

- **영구 정지는 기각** — 오프셋은 Apply 호출 사이 조각상수라 Now의 진행률은 항상 1. 클램프는 오프셋 감소폭 > 경과시간인 순간에만 개입하며 정지 길이는 EMA 스텝(≤ 0.25·|Δoffset|)으로 유계. 반복 감소의 누적 정지도 Σ(스텝)으로 유계.
- **상시 바이어스는 확정** — RTT/2 보정 없이 offset = 진오프셋 + s2c 편도지연. 클라 Now가 서버보다 편도지연만큼 어긋나며, 히트 시각으로 전달 시 오차 ≤ 편도지연(측정: bias=50.0ms 주입 → 오차 50.0ms, T5).

## 결정

1. **Phase A (본 릴리스)** — 동기화 계약을 XML로 명시(진행률 1·스톨 상계·바이어스 상한·단조·스레드 비안전)하고 결정론적 계약/측정 테스트 T1~T5를 추가한다. 코드 로직은 무변경 — 사소·유계 결함에 즉시 수정은 과잉(YAGNI).
2. **Phase B (게이트)** — 편도 보정(`serverTime − RttMs/2000`)은 T5 측정 결과가 유의미함을 보일 때만 별도 항목으로. 리스크: RTT EMA 품질에 따른 과잉 보정, 기존 히트 판정 시간 의미 변화.
3. 계약은 사용자 가시(XML) — ADR-0022에 따라 버전 상승(0.20.0).

## 기각한 대안

- 즉시 RTT/2 보정: 측정 전 수정은 결함 확정을 앞서는 것(감사 정의 위반) + 과잉 보정 리스크.
- 클램프 제거: 단조 보장은 보간 안정성의 전제.

## 결과

- 계약(0.20.0): 오프셋 감소 시 최대 0.25·|Δoffset|만큼 renderTime이 정체할 수 있고(미세 스터터), 클라 Now는 s2c 편도지연만큼 바이어스된다. 히트 시각 오차 ≤ 편도지연.
- 측정 로그: `[TIM-001] bias=50.0ms ... 오차=50.0ms (≤ 편도지연), 위치 오차=0.500m` — Phase B 게이트 자료로 보존.
- 검증: EditMode 273/273(job `5689d72a`)·PlayMode 47/47(job `06082f6b`) — T1~T5 결정론 테스트 포함.
