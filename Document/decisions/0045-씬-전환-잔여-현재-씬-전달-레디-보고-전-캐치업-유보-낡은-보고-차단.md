# 0045. 씬 전환 잔여 — 현재 씬 전달·레디 보고 전 캐치업 유보·낡은 보고 차단

- **상태**: 승인됨
- **날짜**: 2026-10-20
- **결정자**: 사용자 승인 방향(부모 확정 설계) · worker 구현

## 배경 (Context)

ADR-0035 씬 전환의 잔여 결함 3종(상용 점검 SCN-001~003, 조사 `aa6c5b85`). ① 게이트 완료 시 `_pendingScene=null` — 이후 접속자는 현재 네트워크 씬을 **영구히** 못 받고(씬 객체 baseline은 클라 등록 전 lookup-miss로 조용 폐기) ② wire 11 송신 직후 즉시 캐치업 — 씬 로드/등록 전 도착한 전체상태가 무음 폐기되고 서버 스냅샷은 이미 갱신돼 초기값 재전송 없음 ③ 동명 재전환에서 낡은 ready 보고가 이름 검사를 통과해 조기 게이트 완성 가능(타임아웃/취소는 ADR-0035 계약상 게임 책임).

## 결정 (Decision)

1. **현재 씬 추적(SCN-001)** — `CheckSceneGate` 완료 시 `_pendingScene`을 `_currentScene`에 기록. `RunPostApproval`은 `_pendingScene ?? _currentScene`을 wire 11로 전송 — 완료된 전환의 씬이 후발 접속자에게 도달한다. 전환 이력 없는 신규 서버(`_currentScene` null)는 현행 동작 그대로.
2. **레디 보고 전 캐치업 유보(SCN-002)** — wire 11을 받은 연결은 `AwaitingSceneReady`로 게임 데이터(캐치업·복제 틱·스폰/파괴 브로드캐스트·SetOwner/ResumeSession 통보)를 ready 보고까지 유보 — CON-001 승인 유보 패턴의 확장(기존 `VersionApproved` 필터 지점에 동일 조건). 보고 시점엔 클라 등록 완료 후(`UniNetManager.OnSceneLoaded`: 등록→보고 순서)라 전체상태 폐기 창이 소멸한다. 모든 유효 보고에서 `RunPostSceneReady`로 재배정·캐치업을 실행(기존 참여자의 누락 통보·값 및 보류된 고아 입양 복구). `ClientConnected`는 유보된 신규 attach 꼬리에서만 1회 실행하고, 구독자 예외와 무관하게 게이트 평가는 `finally`로 보장 — 승인(CON-001)+씬 레디 2단계가 겹칠 때 post-approval은 "승인 완료 + 씬 유보 없음(또는 ready)"일 때만 실행된다. **재배정의 KEEP 판정은 씬 유보와 무관하게 승인 연결을 생존으로 취급** — 재전환이 기존 소유자의 소유권을 훔치지 않는다(고아 수령 후보만 ready 연결로 제한). 클라가 씬 에셋 실패로 영구 미보고 시 유보 지속 — 킥/재시도는 게임 책임(ADR-0035 계약 유지).
3. **낡은 보고 귀속(SCN-003)** — per-connection `SceneLoadSent` 플래그 + 씬 전환 세대(generation) 카운터: `LoadScene` 시작 시 전 연결 리셋·세대 증분, wire 11 송신 시 설정·세대 증분. **현 전환에서 그 연결에 wire 11을 보낸 이후의 보고만 수용** — 보내기 전 도착한 낡은/위조 보고로 인한 조기 게이트 완성만 차단한다. 새 wire 11 송신 뒤 도착한 이전 동명 씬 보고까지 검증하는 계약은 아니다. 전환 토큰/와이어 변경은 금지(범위 밖). 진행 중 전환이 없으면 보고는 `_currentScene`에 귀속(후발 접속자의 유보 해제). 리뷰 라운드에서 보강된 메커니즘: 생성 wire-12 핸들러가 **디스패치 수신 시점**(메인 큐 처리 전)에 `CaptureSceneLoadGeneration(connId)`으로 세대를 캡처해 메인 큐로 전달하고, 서버는 캡처 세대가 현재 세대와 일치하는 보고만 수용한다 — 플래그만으로는 막지 못하는 "송신 직후~메인 큐 처리 사이" 낡은 보고 창을 닫는다. 와이어 페이로드는 불변이며, 생성기는 0.2.11로 범핑(구 생성 코드용 2인자 `OnClientSceneLoaded` 오버로드 유지로 소스 호환).

## 결과 (Consequences)

- **긍정**: 후발 접속자가 완료된 전환의 씬을 받고(영구 누락 폐쇄), 정상 자동 보고 경로에서 등록 후 캐치업하며, 해당 연결의 wire 11 송신 전 도착 보고가 게이트를 오염시키지 않는다. 아래 tokenless 한계는 유지된다.
- **부담 / 리스크**:
  - 씬 유보 중 연결은 게임 데이터를 받지 못한다 — 영구 미보고 클라는 무기한 유보(연결 슬롯 점유). 킥/타임아웃은 게임 책임(ADR-0035).
  - 동명 재전환에서 **전송 중인**(이미 송신된 wire 11에 대한) 보고는 근본적으로 구별 불가(와이어 토큰 없이) — 송신 이후 도착한 보고는 수용된다. **수용된 범위 밖 잔여**: 조기 유보 해제·게이트 완료 가능성이 남으며 캐치업 유보나 등록 멱등이 이를 완전히 막는다는 보장은 없다. 전환 토큰·wire 11/12·공개 시스템 채널 시그니처 변경은 승인 범위 밖이다.
  - 씬 유보는 승인(CON-001)과 독립적으로 부과된다 — 전환이 없으면(한 번도 없었으면) 유보도 없다(현행).
- **폐기 방법**: `_currentScene` 필드·`AwaitingSceneReady`/`SceneLoadSent`/`CatchupHeld` 플래그와 필터 조건을 제거하고 `RunPostApproval`을 즉시 캐치업으로 되돌린다.

## 마이그레이션

와이어·페이로드 불변. 생성기 0.2.11(생성 wire-12 핸들러가 디스패치 수신 시점 세대를 캡처하는 3인자 `OnClientSceneLoaded(conn, scene, generation)` 호출로 변경 — 패키지 동봉 DLL이라 소비자 조치 없음)과 신규 공개 API 2종(`CaptureSceneLoadGeneration`, 3인자 오버로드 — 수동 보고용; 구 생성 코드 호환 2인자 오버로드 유지)이 추가됐다. 동작 변경(후발 접속자의 wire 11 수신·보고 전 게임 데이터 유보)은 프레임워크 계약 강화로 게임 코드에 투명하다(보고는 UniNetManager가 자동 수행).

## 변경 이력

- 2026-10-20 (독립 리뷰 r6 정정): 결정 ③·마이그레이션의 "와이어·생성기 무변경" 서술을 구현 실제(리뷰 라운드 보강 — 디스패치 수신 시점 세대 캡처, 생성기 0.2.11, 신규 공개 API 2종·구 오버로드 호환 유지)로 정정. 승인 범위(전환 토큰·wire 11/12 불변)는 동일하게 유지.
