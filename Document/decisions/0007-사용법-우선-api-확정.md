# 0007. 사용법 우선 API 확정

- **상태**: 승인됨
- **날짜**: 2026-09-14
- **결정자**: DS + pi

## 배경 (Context)

- 스파이크 1(소스젠 2종의 Unity 컴파일 파이프라인 동작 검증)이 Roslyn 버전 문제로 일시정지 상태다.
- 그러나 UniNet의 본질적 리스크는 전송 기술이 아니라 **공개 API 설계**다. 원칙 "사용은 간단하게"의 적합성은 게임 개발자가 실제로 쓰는 코드 형태로만 검증할 수 있다.
- 구현을 먼저 하면 API가 구현 관점에서 역설계되기 쉽다. 반대로 사용법(이상적인 게임 코드)을 먼저 확정하면 API 계약이 조기 고정되고, 구현은 그 계약을 따르게 된다.

## 결정 (Decision)

1. **실제 구현에 앞서 Sandbox에서 사용법 코드를 먼저 확정한다** (사용법 우선 개발).
   - 최소 수직 슬라이스: 연결 시작 1개(`UniNetManager`) + `NetworkBehaviour` 1개(`ServerRpc` 1·`ClientRpc` 1·`[Replicated]` 1)
   - 위치: `Sandbox/Assets/Usage/` (`Player.cs`, `UsageBootstrap.cs`)
2. **공개 API 스타일은 Mirror/Netcode류 속성 네이밍으로 확정한다.**
   - `[ServerRpc]` (클라→서버), `[ClientRpc(Delivery)]` (서버→클라들), `[Replicated]` (서버 권위 변수)
   - `NetworkBehaviour.IsOwner` (소유권 판단), `UniNetManager.HostAsync/ServerAsync/ClientAsync` (정적 진입점, Task 반환)
3. **Package에는 컴파일 가능한 API 스텁만 둔다.** 속성·클래스 시그니처만 정의하고 본문은 `NotImplementedException`. 계약이 컴파일로 고정된다.
   - 계약 타입(`Delivery`, RPC/Replicate 속성)은 순수 C#인 `UniNet.Core`, 바인딩(`NetworkBehaviour`, `UniNetManager`)은 `UniNet.Unity`에 둔다.
   - `Delivery`는 사용 분(`ReliableOrdered`, `Unreliable`)만 우선 정의한다. DRPC 전달 모드 5종 매핑은 구현 단계에서 확정.

## 결과 (Consequences)

- **긍정**: API 설계가 코드로 조기 고정되어 구현 완료 정의가 명확해진다. 소스젠 블로커와 무관하게 진행된다. 사용법 코드가 그대로 문서·샘플이 된다.
- **부담 / 리스크**: 스텁은 동작하지 않으므로(`NotImplementedException`) 실행 검증은 별도다. API 스타일을 바꾸면 사용법 코드·스텁·문서를 함께 고쳐야 한다. 구현 중 DRPC 계약 매핑에서 속성 시그니처 조정이 필요할 수 있다.
- **폐기 방법**: API 스타일을 바꾸는 새 ADR로 본 결정을 대체하고, 사용법 코드·스텁을 재작성한다.

## 변경 이력

- 2026-09-14 — API 확장: **RepNotify**(변경 콜백 — `[Replicated(Notify = nameof(...))]`, 콜백은 이전값 1개 인자, 현재값은 필드에서 직접 읽음)와 **MulticastRpc**(서버 → 서버+전 클라, `[MulticastRpc(Delivery)]`) 추가. 사용법(`Player.cs`)·스텁(`ReplicatedAttribute` 확장, `MulticastRpcAttribute` 신설) 확장, batch 컴파일 녹색.
- 2026-09-14 — MulticastRpc 클라 호출 시 동작 계약 고정 (리뷰 반영): 클라에서 호출하면 **로컬에서만 실행**되고 서버·타 클라에 전파되지 않음 (UE NetMulticast 패리티) — 속성 XML doc·사용법 주석에 명시.
