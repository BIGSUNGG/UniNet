# 0029. 네트워크 통계 API

- **상태**: 승인됨
- **날짜**: 2026-10-12
- **결정자**: /list 항목 4 (네트워크 통계 API)

## 배경 (Context)

상용 서버 운영(비용 산정·대역폭 튜닝·임계치 알림)과 P3 예산 정책의 효과 검증에 측정 계기가 전무했다 (실사용 갭 검토 2026-10-12 치명 ③). 제약: 상류(DRPC/Communication/RUDP)가 전송계층 바이트 카운터·피어 RTT를 노출하지 않는다(`NetPeer` 비공개) — ADR-0021 패키지 고정으로 상류 수정도 불가.

대안: (a) UniNet 계층 계측(채택 — 측정점을 UniNet이 소유) (b) 상류 통계 대기(불가) (c) 소켓 레벨 별도 계측(프레임워크 밖, 오버엔지니어링).

## 결정 (Decision)

1. **UniNet 계층 트래픽 카운터** `UniNetTrafficCounters` — 송신은 생성 허브의 모든 Send* 메서드(시스템 메시지 1-6·UniNetSend)에서 페이로드 길이 계상, 수신은 생성 허브의 모든 수신 핸들러·디스패치 람다에서 계상. Interlocked 스레드 안전. **측정 계약: RPC 파라미터 페이로드 바이트** — 와이어 프레이밍(메서드 헤더)·전송 오버헤드(UDP/RUDP/ACK/DTLS)는 제외. "얼마나 상태를 실어 나르는가"의 애플리케이션 관점 대역폭이지 소켓 바이트가 아님을 문서가 명시한다. 서버: `NetworkServer.TrafficStats`, 클라: `NetworkClient.TrafficStats`.
2. **자체 RTT 프로브(와이어 8/9)** — 클라 드라이버가 1초 주기로 핑([프로브 원점 시각][현재 RTT])을 보내고 서버 허브가 원점을 에코한다. 클라는 왕복을 **Stopwatch 도메인**(스레드 안전 — Unity 시계는 메인 스레드 전용이라 디스패치 스레드에서 예외)으로 측정해 EMA(α=0.25) 평활 → `NetworkClient.RoundTripTimeMs`. 핑에 실려 온 클라 측 RTT를 서버가 `ServerConnection.RttMs`로 보관(커넥션별 뷰 — 다음 핑까지 1초 지연).
3. **큐 깊이 관측** — `NetworkServer.DeferredSendCount`(P3 예산 초과 지연 큐)·`UniNetEnvironment.PendingMainActions`(메인 펌프 대기열). 제너레이터 0.2.4.

## 결과 (Consequences)

- **긍정**: 운영 관측 기본기 확보. P3 예산·주기 정책의 실측 검증 가능. 에디터 디버깅 툴(후속 항목)의 데이터 원천. Arena가 5초 주기 통계 라인(HUD+로그)으로 사용 예시.
- **하위호환**: 신버전(0.2.4+) 클라가 구버전(≤0.2.3) 서버에 접속하면 미등록 메서드 8 핑을 보내지만 DRPC 디스패치는 미등록 one-way 호출을 조용히 무시한다(상류 HubBase.ProcessRequestCoreAsync — 미등록 시 one-way는 오류 응답 없이 return) — 로그 스팸·예외 없음. 반대로 구버전 클라는 핑을 안 보내므로 서버 RTT는 -1로 유지된다(관측 결손일 뿐 동작 영향 없음).
- **부담 / 리스크**: 페이로드 바이트는 실제 소켓 바이트보다 작다(프레이밍·재전송·ACK 제외) — 비용 청구가 아니라 애플리케이션 대역폭 관찰용(문서 명시). RTT 프로브 트래픽 16B/s·연결(측정 오버헤드 무시 가능). 서버 RTT는 클라 보고값 기반(클라가 거짓 보고 가능 — 관측용이며 권위 판정에 쓰지 않는다).
- **폐기 방법**: 상류가 전송계층 통계·피어 RTT를 노출하면 카운터 소스를 교체한다(공개 API 불변).
