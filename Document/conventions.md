# conventions — 코딩 및 문서 규약

모든 코드는 아래 규약을 따른다. 리뷰어(reviewer 에이전트)가 이 규약 위반을 검사한다.
규약을 추가·변경할 때는 ADR을 남기고 이 문서와 [[changelog]]를 갱신한다.

## OOP / SOLID (필수)

코드 구현은 항상 객체지향 원칙과 SOLID를 지킨다.

- **SRP (단일 책임)**: 클래스/모듈은 하나의 변경 이유만 가진다. 여러 역할이 섞였으면 분리한다.
- **OCP (개방-폐쇄)**: 확장에는 열리고 수정에는 닫힌다. 분기가 늘어나는 대신 다형성·전략으로 확장한다.
- **LSP (리스코프 치환)**: 파생 타입은 기반 타입 계약을 위반하지 않는다. 예외 던지기·사전조건 강화 금지.
- **ISP (인터페이스 분리)**: 사용하지 않는 메서드에 의존하지 않는다. 인터페이스는 작게.
- **DIP (의존 역전)**: 상위 모듈은 추상(인터페이스)에 의존한다. 구체 타입 직접 생성 대신 주입.

동시에 **과잉 추상화 금지**: 구현이 하나뿐인 인터페이스, 한 번만 쓰이는 설정, 미래를 위한 유연성은 만들지 않는다. YAGNI.

## C# / .NET 관례

- 공용 타입·메서드는 PascalCase, 지역 변수·매개변수는 camelCase, private 필드는 `_camelCase`, 인터페이스는 `I` 접두사
- 파일 안에 공용 타입 1개 (내부 보조 타입은 허용)
- `var`는 타입이 명확할 때만
- null 허용 참조 타입(`nullable`) 활성화 권장
- 비동기는 `async`/`await`, fire-and-forget 금지 (명시적 처리)
- 공용 API에는 XML doc 주석

## 오류 처리

- 예상 가능한 오류는 예외가 아니라 반환값/결과 타입으로 표현할 수 있게 검토한다
- 신뢰 경계(사용자 입력, 외부 데이터, 네트워크)에서는 반드시 검증한다
- 삼키는 catch 금지 — 최소한 로그와 재throw 또는 명시적 처리

## 테스트

- 하나 이상의 실행 가능한 확인(단위 테스트 등)을 남긴다 — 로직이 깨지면 실패하는 가장 작은 것
- 테스트 프레임워크: (미정 — 도입 시 기록)

## 문서 규약

- 모든 문서는 **한국어** (코드·기술 용어는 영어)
- 파일명 kebab-case, 위키링크 `[[문서명]]` 사용
- 기능 문서는 `_templates/feature.md`, 결정 기록은 `_templates/adr.md` 구조를 따른다
- 변경 기록은 [[changelog]]에 날짜 그룹으로 누적
